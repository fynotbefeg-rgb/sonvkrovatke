# Принятые тексты — pending-пакет для регистрации

Пакет подготовлен без сетевых записей из PR49 (три хука) и PR50 (точная выбранная
основа). Содержание принято Романом через владельца. Ревизия2 соответствует
описанной Windows-регистрации новой SEO-темы; перед записью требуется свежее
подтверждение именно этой темы, названия и ревизии.

`pending-manifest.json` содержит три pending_approval варианта. Из него штатным
prepareSharedReview сформирован `pending-shared-review.json`; основа и хуки
сохранены без изменений, платформа/концовки не придуманы. Проверен SHA-256 основы
из body-decision.json и ограничение8КБ. Нет approved_by/approved_at, квитанций,
секретов или разрешений производства. Это не авторитетный снимок согласований.

Облачный `topic_review_probe` проверяет выбранную тему только чтением. Его успешный
ответ не означает, что речь уже зарегистрирована/утверждена. Сам probe ничего не
добавляет в Google. Устаревшая проверка disabled snapshot сохраняется для старого
режима; не запускать её для проверки включённой темы.

Штатный отправитель pending-речи по-прежнему требует editorial release. Для этой
основы нельзя выдумывать прохождение всех gates: демонстрация GSC/OpenSEO не
выполнена, стоимость всей связки/исходное R06 не пройдены, метрики внешнего видео
не перепроверены. Угол честного обзора со стоимостью Роман принял, но код фильтра
пока требует бесплатного решения. Эти ограничения нужно разрешить явно в
редакционной политике/пакете, не обходить отправитель прямым POST.

Следующий шаг: подтвердить свежую квитанцию темы и показать владельцу точные
оставшиеся редакционные ограничения. Не просить повторно выбрать тему или основу.
