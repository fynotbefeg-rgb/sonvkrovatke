# Учебные данные для будущих демонстраций

Все люди, компании, цены и документы вымышлены. Домены .example предназначены для примеров. Это подготовка входных данных и ожидаемых результатов, а не запущенная n8n/Gemini/CRM-интеграция и не кейс Романа.

## Состав

- lead/input.json и lead/request.eml: заявка мастерской, известные контакт и срок, неизвестные бюджет и телефон. Ожидаются карточка и черновик ответа, без отправки.
- invoices/input.json и два PDF: разные суммы, сроки и валюты. invoice-001-replay.pdf повторяет первый файл побайтово. В обработке должны остаться две уникальные строки; валюты не смешивать.
- proposal/input.json, price-book.json и template.md: анкета, вымышленный фиксированный прайс и шаблон. Ожидаемый итог — 17 500,00 RUB, сроки условны; готовое предложение пока не создано.
- expected-results.json: эталонные значения и критерии; это не результаты модели.
- manifest.json: SHA-256 входов, файлов и эталона; workflowTested=false.
- validation-report.json: выполненные проверки файлов; не проверка бизнес-конвейера.

PDF содержат текстовый слой и пометку «НЕ ДЛЯ ОПЛАТЫ», реальных банковских/налоговых реквизитов нет. Они подходят для первого теста извлечения текста; распознавание фото, OCR и плохих сканов пока не проверяется.

## Проверка после выбора Романа

Передавать будущему обработчику только input.json/EML/PDF/анкету/прайс. expected-results.json оставить стороне проверки: не подмешивать эталон в запрос извлечения, иначе тест будет подсказанным.

1. Для заявки сравнить поля; неизвестные значения оставить пустыми и повторить тот же Message-ID.
2. Для счётов обработать два PDF и повтор первого; сравнить Decimal-суммы и валюты, не создавать третий документ.
3. Для предложения заполнить свой шаблон из анкеты/прайса; сверить состав услуг и сумму, затем визуально проверить документ.

Даже успешный тест учебных данных не подтверждает устойчивость реальной почты, OCR, CRM, расписания или авторизацию. Темы, речь и хуки не утверждены; ничего не отправлять клиентам, не оплачивать и не включать в производство.

## Повторная сборка

Из корня репозитория:

```bash
python roman-reels/scripts/build-business-demo-fixtures.py
```

Нужны Python, ReportLab и шрифт DejaVuSans (в текущей облачной среде доступны). Для другого шрифта: --font /путь/к/DejaVuSans.ttf. Скрипт локально строит учебные EML/PDF, проверяет арифметику и сохраняет контрольные суммы. Существующие файлы с отличающимися байтами не перезаписывает. Никаких сетевых вызовов.
