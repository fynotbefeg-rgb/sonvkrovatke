# Расширенная проверка учебного сайта

Реальный локальный запуск браузера 2026-10-10. Сохранённые сценарии Playwright
на одном учебном сайте в двух состояниях. Это не автономный аудит Claude,
не MCP-протокол и не эксперимент «один промпт». Проверки написаны Codex.

| Проверка | С ошибками | После исправлений |
| --- | --- | --- |
| Четыре ожидаемые страницы | FAIL: /pricing 404 | PASS: все 200 |
| Изображение на главной | FAIL: отсутствующий ресурс | PASS: изображение загружено |
| Десктопное меню → услуги | PASS | PASS |
| Мобильное меню → заявка | FAIL: не раскрывается | PASS: переход выполнен |
| Горизонтальное переполнение, 390 px | FAIL: контент шире экрана | PASS |
| Пустая форма | FAIL: отправляется | PASS: браузер блокирует |
| Неверный email | FAIL: отправляется | PASS: браузер блокирует |
| Получение заявки | FAIL: «принята», записи нет | PASS: запись в учебном приёмнике |
| Повтор той же заявки | FAIL: две записи | PASS: две отправки, одна запись |

До исправлений: 1 PASS / 8 FAIL / 0 BLOCKED. После: 9 PASS / 0 FAIL / 0 BLOCKED.
Это 8 специально заложенных нарушений требований, а не статистика найденных
ошибок случайного клиентского сайта. Исправления заданы автором учебного
сайта, а не выполнены healer. Набор проверок одинаковый в обоих запусках.

## Доказательства

evidence/audit-report.json содержит наблюдения, HTTP-ошибки, данные приёмника,
размеры экрана, версию браузера/Playwright, хеши сценариев и fixture-site.mjs.
evidence/ — 18 скриншотов, по одному в конечном состоянии каждого сценария.
Скриншот сам по себе не подтверждает HTTP-код или получение заявки: для этого
нужны записи отчёта. Мобильный дефект переполнения и исправленная форма
дополнительно проверены визуально.

Использован уже установленный playwright-core 1.64.0-alpha-1790635538000;
это версия исполнителя эксперимента, не рекомендация стабильной версии.
Chromium Headless Shell в текущем контейнере запускается только с явным
local-demo opt-in без browser sandbox и доступом к локальным сокетам.
Browser requests ограничены origin собственного loopback сервера. Не
переносить эту настройку на публичные/авторизованные сайты.

## Повторение

Из корня репозитория, с уже установленным playwright-core и подходящим
браузером, в новую папку вывода:

```bash
node roman-reels/scripts/run-site-audit-demo.mjs \
  /path/to/dependency-root /path/to/chromium /tmp/fresh-site-audit-evidence
```

В текущем изолированном окружении дополнительно требуется
SITE_AUDIT_DEMO_NO_SANDBOX=true; это исключение для собственного учебного
loopback сайта. По умолчанию runner требует browser sandbox. Он сам поднимает
временный сервер и закрывает его после проверки; чужие сайты не посещает.

Успешный exit означает: восемь известных нарушений отличены от исправленной
версии. В raw-отчёте сломанный сайт остаётся FAIL. Проверки не пропускались
и требования не ослаблялись. Реального CRM, доставки email, постоянного
хранилища, iPhone, полного WCAG/SEO/security/performance аудита здесь нет.

## Вывод для ролика

Показать две-три разные проблемы и пользу сохранённых проверок:
например, мобильный путь к форме и ложное сообщение «заявка принята».
Нельзя говорить, что «ИИ сам нашёл восемь ошибок одним промптом» или
«проверил абсолютно весь сайт». Автономный поиск/написание тестов через Claude
или Test Agents — отдельный ещё не выполненный эксперимент. Новая речь,
хуки, ролик и запуск в производство не подготовлены и не утверждены.
