# Windows MCP: наблюдения учебного SEO-стенда, 2026-10-11

Собраны локальной сессией Claude Code на Windows 10 Pro 22H2 через инструменты Playwright MCP этой сессии (Edge 155 headless). Это не облачный Playwright-скрипт и не автономный аудит. Стенд — собственный `serve-seo-fixture.mjs` на 127.0.0.1, все данные вымышлены.

## Что это

Два заранее подготовленных состояния одного учебного сайта: `broken` с заложенными ошибками и `fixed`. Ошибки заложены в код стенда, их не находил и не исправлял ИИ. Наблюдения показывают, что инструменты MCP на Windows реально собирают нужные поля, и ничего больше.

- `observations.json` — основной опыт на коммите db1adac: четыре страницы, robots.txt, sitemap.xml, `/old-services`, `/missing-test-page` в обоих состояниях. Порты 50492 (broken) и 50645 (fixed).
- `gone-observation.json` — отдельная дополнительная проверка `/gone` из broken-sitemap в новой сессии (порт 63444, коммит 026e5c6, код стенда не изменился). Она не относится к старым портам.
- Четыре PNG — снимки главной и `/services` в обоих состояниях, 1280×800, полная страница.
- `manifest.json` — размеры, SHA-256, редактирование, среда.

## Как получены данные

- HTTP-статус страницы: `performance.getEntriesByType('navigation')[0].responseStatus` через `browser_evaluate` после `browser_navigate`.
- Редиректы: исходный код из `browser_network_requests`, заголовок `Location` из `browser_network_request` (response-headers) — до итоговой страницы.
- title, description, meta robots, canonical, число H1 — из DOM через `browser_evaluate`.

## Важно про снимки `/services`

`broken-services.png` и `fixed-services.png` побайтно одинаковы (одинаковый SHA-256). Отличия `/services` — title, description, canonical — находятся в `<head>` и на экране не видны. Различие доказывают JSON-наблюдения, а не снимки.

## Обнаруженные конфликты в broken и проверяемые правки

| # | Наблюдение (broken) | Предлагаемая правка | Как проверить | fixed |
|---|---|---|---|---|
| 1 | Главная: `meta robots = noindex`, хотя стенд намерен её индексировать | Убрать `noindex` с главной | meta robots = `index,follow` | да |
| 2 | Главная: 2 H1 | Оставить один основной H1 | число H1 = 1 | да |
| 3 | `/services`: title совпадает с главной | Собственный title страницы | title уникален | да |
| 4 | `/services`: нет meta description | Добавить description | поле присутствует | да |
| 5 | `/services`: canonical указывает на `/` | canonical на саму страницу | canonical = URL страницы | да |
| 6 | robots.txt: `Disallow: /services` | Снять запрет для страницы, которую хотят показывать | `Disallow` пустой | да |
| 7 | sitemap.xml: нет `/services`, есть `/gone` | Перечислить реальные страницы, убрать несуществующие | список = 4 страницы | да |
| 8 | `/gone` из sitemap отвечает 404 | Не держать в sitemap адреса с 404 | статусы URL из sitemap = 200 | `/gone` удалён из sitemap; сам `/gone` в fixed не запрашивался |
| 9 | `/old-services`: 302 → `/` | Постоянный 301 на соответствующую страницу | 301, Location `/services` | да |
| 10 | `/missing-test-page`: 200 при содержимом «Не найдено» (soft-404) | Отдавать настоящий 404 | статус 404 | да |

Канонический URL на себя, один H1 и состав sitemap — условия этого учебного стенда, а не универсальные правила для любого сайта. Не всякий сайт должен открывать все страницы для индексации.

## Чего эти данные не показывают

- Реального индексирования в Google: снятие `noindex` убирает конкретный запрет, но индексацию не гарантирует. Позиции и трафик не измерялись и не обещаются.
- Search Console, скорость, Core Web Vitals, безопасность, доступность, контент, JS-рендеринг, реальные сайты.
- Бесплатность полной связки для зрителя: Claude Pro/Max — инструмент разработки, стоимость пути для зрителя проверяется отдельно.
- Утверждения речи или темы Романом. Сценарии и approved-статусы этим PR не меняются.
