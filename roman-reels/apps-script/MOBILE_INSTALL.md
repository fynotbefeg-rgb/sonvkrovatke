# Установка дополнением с iPhone

Этот способ сохраняет исходный `Code.gs`: не требуется выделять или заменять его целиком. Он рассчитан на старый код, видимый на скриншотах пользователя; фактическое выполнение и идентичность Google ещё требуют проверки.

## Состояние перед установкой

Пользователь добавил разрешённый Google email Романа в `ROMAN_APPROVER_EMAILS` и сообщил о замене `ROMAN_REELS_WEBHOOK_TOKEN` в Google и GitHub. Read-only Actions run [37986175127](https://github.com/fynotbefeg-rgb/sonvkrovatke/actions/runs/37986175127) на коммите `944008e` успешен: очередь 0. Выполнялся только `google-queue`, Remotion/Apify пропущены. Это подтверждает доступ с текущим секретом, но не внедрение защищённых утверждений.

## Установка

1. В текущем Apps Script открыть редактор `<>`, нажать `+` у Files → Script, назвать файл `RomanApproval`.
2. В новый файл вставить весь [RomanApproval.gs](RomanApproval.gs). Старый файл целиком не трогать. Если в новом файле Google создал пример `myFunction`, заменить только этот маленький пример.
3. В **старом** `Code.gs` изменить только `function doPost(e)` на `function legacyDoPost(e)`. В проекте должен остаться ровно один глобальный обработчик `doPost`: в новом файле. Нельзя переопубликовывать проект между шагами 2 и 3. Старый deployment до переопубликации использует сохранённую опубликованную версию.
4. Сохранить проект. Выбрать и выполнить новую `setupRomanApproval`; подтвердить права Google. Она добавляет edit-триггер, не удаляя старые таймеры.
5. Обновить **существующий** web app deployment новой версией, сохраняя URL и параметры доступа. Без этого GitHub продолжит обращаться к старой очереди.
6. Проверить read-only запрос очереди. Затем проверить единичное утверждение именно Романом из разрешённого Google аккаунта и отзыв при изменении текста. Установку нельзя считать законченной, пока Google не передаст идентичность реального редактора и очередь не вернёт полный проверенный манифест.

Новый код изолирован внутри `RomanApprovalV1`, поэтому старый `SPREADSHEET_ID` и старые вспомогательные функции не конфликтуют. Точка POST обращается исключительно к новому проверенному механизму. Старые функции чтения очереди и таймеры остаются legacy: ручной запуск старого `getApprovedProductionQueue` не является проверкой новой защиты. Для новой очереди использовать `romanApprovalQueueV1`, для сверки/отзыва — `romanApprovalSafetyV1`.

Старый таймер может отметить строку «Готов к производству» по одному dropdown. Новый POST такую строку не выдаст без доверенной квитанции, допустимого редактора и совпадающего текста/ревизии/хеша. До реального edit-триггера этот статус нельзя считать разрешением на производство.

Нельзя одновременно устанавливать это дополнение и полную замену `Code.gs` из репозитория. Для отката вернуть имя старого `legacyDoPost` к `doPost`, убрать новый файл и новый edit-триггер и переопубликовать прежнюю версию. Защищённое производство при откате должно оставаться остановлено.

Генератор дополнения: `node roman-reels/scripts/build-approval-addon.mjs`. Десять mock-тестов, включая сосуществование со старыми именами/таймерами, отказ выдавать строку legacy без квитанции и немедленный отзыв после правки текста, прошли локально. Платные сервисы не вызываются.
