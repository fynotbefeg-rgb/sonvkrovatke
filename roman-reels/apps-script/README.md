# Apps Script: обновление утверждений Романа

Для установки с телефона без замены старого файла подготовлен альтернативный путь: [MOBILE_INSTALL.md](MOBILE_INSTALL.md) и отдельный `RomanApproval.gs`. Он требует только переименования старого `doPost` и добавления нового файла. Ни один путь пока не установлен/переопубликован в Google; способы нельзя смешивать.

`Code.gs` — подготовленная замена всего существующего файла, а не добавление в конец. Исходное поведение сверено по трём скриншотам пользователя от 2026-10-09. В рабочий Apps Script код ещё не установлен и web app ещё не переопубликован. Доступные инструменты не предоставляют запись через Apps Script API.

## Что исправлено

- Существующий токен остаётся в `ROMAN_REELS_WEBHOOK_TOKEN`, никогда не попадает в код или логи. Аутентификация выполняется до чтения очереди или записи черновиков. GET сценариев запрещён, неизвестные действия отклоняются.
- Очередь включает все поля существующего манифеста утверждения: ID темы/хука/версии, ревизию, текст, `status: approved`, дату, email и SHA-256. Хеш совместим с Node-проверкой, включая кириллицу и эмодзи.
- Утверждение принимается только при одиночном ручном изменении G на `Утверждено` от email в разрешённом списке. Фоновый триггер не выдаёт собственную учётную запись за автора правки.
- Доверенная квитанция утверждения хранится в Script Properties, отдельно от изменяемой таблицы. Ручная подстановка H–J и статуса K без квитанции не позволяет получить задание из очереди.
- Изменения A–K отзывают утверждение, кроме разрешённого одиночного утверждения в G. Даже до запуска таймера очередь сверяет текущий текст/ревизию с хешем квитанции и проверяет отсутствие формул и дублей ID.
- Чтение очереди, загрузка черновиков, утверждение и проверка статусов используют ScriptLock. Все черновики проверяются до записи; существующие строки с тем же ID не перезаписываются, включая утверждённые версии.
- Старые функции `checkApprovedScripts`, `checkProductionSafety`, `markApprovedForProduction`, `testConnection` сохранены. Существующие таймеры не удаляются. Новая функция `setupRomanApproval` добавляет только отсутствующий edit-триггер.

## Установка (выполнять последовательно)

1. Сохранить копию прежнего исходного файла и заменить содержимое `Code.gs` подготовленным файлом. Не добавлять его рядом с прежним кодом: повторные объявления функций/констант могут привести к конфликтам.
2. В Script Properties добавить `ROMAN_APPROVER_EMAILS` — фактический Google email Романа (или явно разрешённых утверждающих), несколько через запятую. Email нельзя угадывать по GitHub-профилю. Существующий `ROMAN_REELS_WEBHOOK_TOKEN` оставить на месте.
3. Вручную выполнить `setupRomanApproval` и предоставить запрошенные Google права для таблицы и installable edit trigger. Уже установленные таймеры сохраняются. Эти разрешения относятся к Apps Script, а не к подключению GitHub.
4. В существующем deployment выбрать новую версию web app, сохраняя прежний deployment/URL и настройки доступа. Создание нового URL потребует обновления секрета GitHub, поэтому предпочтительно обновить существующее развёртывание.
5. Проверить на одном тестовом сценарии: Роман меняет G на `Утверждено`; H–J заполняются, K становится `Готов к производству`. Изменение сценария должно отзывать утверждение. Платные сервисы и рендер для проверки не нужны.
6. Запустить только read-only очередь/dry run после проверки входящей папки. Нельзя считать локальные тесты доказательством успешного развёртывания.

Google может скрывать `e.user` у installable edit trigger, особенно при определённых настройках доступа и типах аккаунтов. В этом случае код возвращает решение на проверку и не выдаёт ролик в производство. Подстановка email владельца скрипта была бы небезопасна; потребуется отдельный способ аутентифицированного утверждения. Это проверяется в реальном аккаунте на шаге 5.

Владелец и редакторы Apps Script являются доверенными администраторами: они могут менять код и Script Properties. Квитанции не защищают от администратора скрипта. Изменения через API не вызывают edit-триггер; очередь всё равно сверяет хеш перед выдачей, а таймер отзывает несовместимое утверждение.

Квитанции занимают по одной записи Script Properties на ID ролика. При дальнейшем накоплении месяцев требуется архивирование или внешнее хранилище с учётом квоты Properties; это обновление рассчитано на текущую очередь, а не бессрочный архив.

```bash
node roman-reels/scripts/apps-script.test.mjs
node roman-reels/scripts/manual-intake.test.mjs
```
