## Выбор инструментов речи

Кандидаты пока не установлены в данной среде (кроме FFmpeg).
Для P1 предложен локальный faster-whisper CPU/int8 с пословными timestamp, модель выбирать после
бенчмарка и учитывать загрузку весов/лицензию. Это не forced alignment: качество границ проверять
на слух и контрольных кадрах. WhisperX добавлять если нужна точнее привязка, после измерения RAM
и зависимостей; GPU не предполагать. Silero VAD — отдельная проверка пауз; MediaPipe/OpenCV — позже.
librosa требуется только при реальном монтаже по музыкальному ритму.
Стандартный GitHub runner не считать бесплатным/безлимитным: размер модели, время задания,
доступные минуты и бюджет проверить до вычислительного workflow. Сейчас платных вызовов нет.

## Гарантии исполнения

Существующие production_key и intake job_key не смешивать (см. контракт).
Не хранить SQLite только в checkout/artifact Actions: это не постоянный транзакционный сервер.
Не создавать выбранный cloud backend до согласования размещения и стоимости.
Безопасные повторы: read/download/validation по checksum. Не повторять непонятный submit HeyGen.
History хранит переходы, причину, attempt, worker/lease и контрольные хеши, без токенов/cookies.
Ошибка авторизации/устаревший hash — остановка, а не автоматическая подмена текста.

## Первый доступный этап без Windows

Следующий PR после согласования: reproducible real-speech fixture для одного body1.mp4,
адаптер и подготовка входа C1/C2; затем интеграция реализации Claude и QC.
Наличие MP4 не равно подтверждённому сценарию; development результаты не идут в finished Drive
и Sheets «готово». Если Claude ещё не подключён, Codex готовит данные/проверки и фиксирует зависимость;
не выдаёт самостоятельную разработку монтажа за выполненное Claude задание.
