`scripts/plan-manual-intake.mjs` строит план по снимку утверждений и списку метаданных Drive. Он не скачивает видео, не вызывает AI, не рендерит, не меняет таблицу или Drive. Каждый результат имеет `render_allowed: false`.

Для цельного MP4 (хук + весь сценарий) имя файла:

```text
R-<topic>-h<1|2|3>__r<revision>__<полный SHA-256 script_hash>.mp4
```

Имя назначается по проверенному утверждению, а не по предположению о содержимом ролика. Переименование само по себе не доказывает совпадение речи. Не следует массово переименовывать старые ролики.

Снимок утверждений использует существующий формат манифеста: `items`, поля `topic_id`, `hook_id`, `version_id`, `script_revision`, `hook_text`, `script_text`, `status`, `approved_by`, `approved_at`, `script_hash`. Статус утверждения — `approved`. Хеш: SHA-256 UTF-8 строки `JSON.stringify([version_id, script_revision, hook_text, script_text])`; пробелы и пунктуация сохраняются. Хеш подтверждает целостность, но не удостоверяет личность утверждающего.

Инвентарь:

```json
{"folder_id":"verified-incoming-folder-id","files":[]}
```

`files` — результат `rclone lsjson ... --files-only --max-depth 1 --hash`: требуются `ID`, `Name`, `MimeType`, `Size` (число), `Hashes.md5`. Неоднозначные имена, пустой MP4, отсутствующая контрольная сумма и отсутствие нужной ревизии блокируют задание. Дубли ID и неверный манифест останавливают проверку целиком. Неутверждённые и посторонние файлы не запускают задания.

```bash
node roman-reels/scripts/manual-intake.test.mjs
node roman-reels/scripts/plan-manual-intake.mjs approvals.json inventory.json plan.json
# Необязательный журнал уже завершённых заданий:
node roman-reels/scripts/plan-manual-intake.mjs approvals.json inventory.json plan.json completed.json
```

`completed.json` содержит `items: [{job_key, status: "completed", output_file_id}]`. Ключ включает ID ролика, ревизию, хеш сценария, ID файла Drive и MD5. Повтор выполненного задания пропускается; изменённый MP4 получает новый ключ. Это планирование дедупликации: постоянный журнал и атомарная блокировка производственного задания ещё не реализованы.

`check-production-queue.mjs [approvals.json]` сохраняет снимок только после строгой проверки полного формата и статуса `approved` у каждой записи. Старый вызов без аргумента сохраняет прежнюю проверку доступности. Если действующий Apps Script возвращает неполные записи, экспорт завершится ошибкой; нельзя выдумывать отсутствующие метаданные утверждения.

## GitHub Actions

Новый ручной workflow `roman-manual-intake.yml` работает только в `automation/roman-reels-v1`:

- `tests` по умолчанию: автономные проверки без внешних сервисов.
- `live`: читает аутентифицированную очередь и метаданные входящей папки через сервисный аккаунт с `drive.readonly`; сохраняет план как artifact на три дня. Текст сценария не входит в artifact. Сетевой запрос очереди ограничен 30 секундами; rclone выполняет до трёх попыток.

Для `live` нужны существующие секреты `ROMAN_REELS_WEBHOOK_URL`, `ROMAN_REELS_WEBHOOK_TOKEN`, `GDRIVE_SA_JSON` и новая переменная `ROMAN_INCOMING_FOLDER_ID`. Её следует установить только после проверки реального ID отдельной входящей папки и доступа сервисного аккаунта. Папка готовых работ не является входящей. Workflow не запускается по расписанию или при push.
