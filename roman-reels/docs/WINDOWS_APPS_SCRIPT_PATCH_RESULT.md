## Области видимости обработчиков (поправка к PR #15)

Анализ проводился разбором блоков по глубине скобок. Дополнительно оба файла загружались в один глобальный контекст Node VM в порядке проекта, и для каждого глобального имени определялось, к какой декларации оно разрешается.

- **Один глобальный маршрутизатор.** Глобальный `doPost` — это делегирующая обёртка в конце RomanApproval.gs, она вызывает `RomanApprovalV1.doPost(e)`. Второй `doPost`, а также `onRomanApprovalEdit` и `setupRomanApproval` находятся внутри IIFE `RomanApprovalV1` (глубина 1) и глобальными не являются. Вывод PR #15 о «двух действующих декларациях» неверен.
- **Глобальные имена из Code.gs:** `testConnection`, `legacydoPost` (не вызывается маршрутизатором), `checkApprovedScripts`, `markApprovedForProduction`, `checkProductionSafety`, `getApprovedProductionQueue`, `getProductionQueueResponse`, `doGet`.
- **Глобальные имена из RomanApproval.gs:** `doPost`, `onRomanApprovalEdit`, `setupRomanApproval`, `romanApprovalQueueV1`, `romanApprovalSafetyV1`.
- **Путь `doPost → token → action`:** обёртка → `RomanApprovalV1.doPost`. Сначала проверяются размер и JSON, затем токен из свойства `ROMAN_REELS_WEBHOOK_TOKEN`; при несовпадении возвращается `Unauthorized`. Далее `get_production_queue` идёт во *вложенный* `getProductionQueueResponse` с проверкой квитанций. `add_drafts` или пустой action ведёт к `romanAddDrafts_`, любой другой action — к `Unknown action`.
- **Edit-триггер:** обёртка → `RomanApprovalV1.onRomanApprovalEdit`. Используется проверка `e.user` и списка утверждающих без подстановки владельца.
- **Таймеры (по имени функции):** `checkApprovedScripts`, `markApprovedForProduction` и `checkProductionSafety` разрешаются в **старые** реализации из Code.gs, а не в версии из дополнения. Старые `markApprovedForProduction` и `checkProductionSafety` пишут статус в таблицу через `setValue`. На web-очередь это не влияет: она требует доверенную квитанцию. Но существующие таймеры продолжают выполнять старую логику. Это текущее поведение, кандидат его не меняет. Какие триггеры реально установлены, не проверялось.

Ни одно из этих утверждений не говорит о том, как ведёт себя опубликованная версия: deployment может указывать на старую версию кода.
