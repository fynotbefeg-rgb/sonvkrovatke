# Windows: доступность ноутбука без человека рядом — результат

2026-10-12, около 13:20 по местному времени ноутбука. Задание WINDOWS_SERVER_AVAILABILITY.md (origin/feature/codex-pipeline `28c5a7a`). Выполнено Claude Code на ноутбуке. Использовались только команды чтения: `powercfg /getactivescheme`, `/query`, `/qh`, `/a`, состояние служб, сессий и процессов, журнал System за 7 дней, чтение реестра без паролей. Ничего не менялось и не перезагружалось. Процессы не завершались, вход в HeyGen и Google не выполнялся.

## Итог

Сейчас ноутбук доступен без человека рядом: питание от сети, idle-сон и гибернация от сети выключены, удалённый доступ работает, интерактивная сессия активна.

Есть два реальных риска:

1. **Закрытие крышки = сон** (и от сети, и от батареи). 12 окт. от сети заменено на «Ничего не делать» (раздел 5); от батареи по-прежнему сон.
2. **Перезагрузка Windows Update.** Она уже была 9 окт. 2026 в 12:12. После такой перезагрузки удалённый доступ, скорее всего, вернётся, но сессия Claude, MCP и браузерный профиль сами не запустятся.

## 3. Что мешает unattended работе (по наблюдениям)

1. **Крышка.** До изменения закрытие крышки переводило систему в Modern Standby; от сети это устранено (раздел 5), от батареи по-прежнему Сон. Вывод о связи CRD и браузерной сессии во сне не проверялся (крышку по заданию не закрывали). Считать недоступным.
2. **Перезагрузка обновлением.** 9 окт. 2026 в 12:12 перезагрузку инициировал `TrustedInstaller.exe` с причиной «Операционная система: Обновление (Запланированное)». Перед этим в журнале есть Kernel-Power 41 / EventLog 6008: предыдущее завершение было нештатным. Флага ожидающей перезагрузки сейчас нет. Активные часы обновлений: 8–17, режим «умных» активных часов.
3. **После перезагрузки.** Службы CRD и RustDesk стартуют автоматически и работают в сессии 0. Это даёт удалённый доступ к экрану входа, но **не доказывает**, что после перезагрузки сохранится авторизованная браузерная сессия. Auto-login выключен (включать его задание запрещает). Значит, после любой перезагрузки человек должен удалённо войти в Windows, затем запустить Claude Code и MCP. Входы в Google и HeyGen в профилях браузера, вероятно, сохранятся (cookies на диске), но это не проверено.
4. Idle-сон и гибернация от сети не мешают, они выключены. Экран может гаснуть, на работу это не влияет (сейчас он не гаснет).

## 4. Подготовленные обратимые команды (применены 12 окт. по разрешению владельца, см. раздел 5)

Только для режима AC и только для активной схемы. Батарея, Windows Update, UAC, защита, firewall и auto-login не затрагиваются. Возможно, понадобится консоль с правами администратора. Применять только после согласования владельца, и ноутбук с закрытой крышкой не должен перегреваться (вентиляция).

```bat
:: Применить: закрытие крышки от сети — «Ничего не делать»
powercfg /setacvalueindex SCHEME_BALANCED SUB_BUTTONS LIDACTION 0
powercfg /setactive SCHEME_BALANCED

:: Проверить
powercfg /qh SCHEME_BALANCED SUB_BUTTONS LIDACTION

:: Откат к исходному значению (1 = Сон)
powercfg /setacvalueindex SCHEME_BALANCED SUB_BUTTONS LIDACTION 1
powercfg /setactive SCHEME_BALANCED
```

Остальные AC-таймеры уже в нужном состоянии (сон 0, гибернация 0), их менять не нужно. Исходные значения на случай ручного отката: STANDBYIDLE AC 0, HIBERNATEIDLE AC 0, VIDEOIDLE AC 0, LIDACTION AC 1.

Для перезагрузок обновлениями команд не готовлю: политики Windows Update по заданию не меняются. Порядок восстановления после перезагрузки — только ручной: удалённый вход через CRD → запуск Claude Code → проверка MCP.

Батарейные значения, Windows Update, UAC, защита, firewall и auto-login не менялись. Перезагрузки не было, крышка физически не закрывалась. Откат — команда из раздела 4 (`LIDACTION 1`).
