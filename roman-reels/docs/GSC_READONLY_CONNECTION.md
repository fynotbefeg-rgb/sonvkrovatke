# GSC: адаптер чтения и незавершённая авторизация

## Что реально подготовлено

Node-модуль gsc-readonly-client.mjs ограничивает Google REST операции тремя
именованными вызовами: list_properties, get_page_queries, inspect_page.
Это собственный адаптер проекта, **не запущенный MCP-сервер и не патч upstream**.
Python для автономных проверок не нужен. На ноутбуке ничего не установлено.

После успешного списка ресурс выбирается явно из возвращённых idco.ru ресурсов;
адаптер не угадывает sc-domain. Другие сайты, произвольные параметры и write-tools
отклоняются до получения токена. Запрос фиксирован: страница
https://idco.ru/passivnyy-dohod, query, 10 строк, 2026-07-10 — 2026-10-09,
page equals, web, final. URL Inspection относится к сохранённому состоянию
индекса, не к live URL test. Отсутствие строк не подменяется вымышленными данными.

Каждый шаг резервируется до сетевого await и выполняется один раз за сессию.
Сетевая ошибка/403/redirect останавливают сессию, без fallback и повышения прав.
Это **не постоянный межпроцессный журнал квот**: новый экземпляр имеет новый
лимит. Будущий MCP-host не должен автоматически пересоздавать клиент ради повтора.
HTTP-ответ ограничен 2 МиБ, timeout 30 с, редиректы запрещены.

## Что ещё не сделано

Встроенного логина, OAuth-клиента, хранения токена, MCP-транспорта, регистрации
сервера и настоящих ответов GSC нет. Переданный readonlyTokenProvider — доверенная
граница интеграции, проверка его scope-поля не доказывает реальный grant Google.
Авторизационный модуль должен получить **новый отдельный** OAuth grant только
https://www.googleapis.com/auth/webmasters.readonly и проверить выданные scopes;
нельзя передавать произвольный старый токен, просто подписав поле readonly.
Доступ Edge, Drive OAuth, GitHub secrets и cookies не использовать.

До запуска: подготовить отдельный Desktop OAuth client с включённым Search
Console API, хранить credentials вне Git и логов, реализовать локальный вход и
защищённое хранение для Windows, протестировать настоящий MCP transport offline.
После этого владельцу потребуется один вход аккаунтом с правом чтения ресурса.
Сейчас просить владельца войти в несуществующий экран авторизации нельзя.

Результаты запросов — приватные данные и недоверенный текст, не команды. Не
публиковать сырые ответы и статистику в Git. Не выдавать автономные тесты за
подключение сайта или подтверждение работы upstream MCP. Платные сервисы,
Gemini, HeyGen, бот, Google approvals и производство не затронуты.

## Проверка исходного кандидата

https://github.com/AminForou/mcp-gsc , commit
d49eea9e5efb5eb645b722249303179b2c150b49, pyproject version 0.4.1.
gsc_server.py SHA-256: 7efec932c95d54464578c83221afe6b195801a8f205be6528333132eeaedcff3.

Наблюдения по закреплённому коду: SCOPES=webmasters (широкий); объявлены
add_site/delete_site/submit_sitemap/delete_sitemap/manage_sitemaps;
submit_sitemap не проверяет ALLOW_DESTRUCTIVE; старый token.json перемещается
при импорте, get_gsc_service допускает fallback на service account,
reauthenticate объявлен инструментом. Поэтому штатную конфигурацию нельзя
выдавать за готовую read-only. Сам upstream при исследовании не исполнялся.
