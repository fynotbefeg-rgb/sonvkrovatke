# Узкий сценарий: проверить путь от кнопки до страницы заявки

Источник замечания — переданное владельцем сообщение Романа. Основа v2
слишком общая. Предлагаемое сужение: подключить Playwright MCP и проверить
конкретную кнопку после изменений сайта. Это функциональная проверка,
не SEO-аудит и не доказательство потерянных продаж. Выбор темы в Sheets
не меняется автоматически; новая тема/речь возвращаются Роману на проверку.

## Что проверено 10 октября 2026

- Официальный Microsoft репозиторий: https://github.com/microsoft/playwright-mcp
- Установка/статус MCP в Claude Code: https://code.claude.com/docs/en/mcp
- Через npm установлен @playwright/mcp **0.0.83**, Node.js >=18.
- Реальный MCP stdio-клиент получил browser_navigate, browser_click,
  browser_take_screenshot; применены к нашему учебному localhost-сайту.
- Кнопка «Оставить заявку» в broken fixture: переход /missing-lead, HTTP 404,
  видимая ошибка; fixed fixture: /contact, HTTP 200 и нужная страница.
- Сохранены реальные скриншоты, snapshots и demo-report.json.

Это реальный тест MCP, но тестовый сайт намеренно содержит ошибку. Клиентский
сайт и продажи не проверялись. Claude Code/его подписка в демонстрации не
запускались: действия вызвал программный MCP-клиент из Codex. Конфигурация
Claude подтверждена документацией, не отдельным сеансом Claude.

## Подключение — для будущего демонстрационного компьютера

Предпосылки: Node.js, Claude Code и совместимый установленный браузер.
Официальный stdio-способ, закреплена протестированная версия:

```sh
claude mcp add --transport stdio playwright -- npx -y @playwright/mcp@0.0.83 --headless --isolated
```

Проверить `/mcp` в Claude: запись конфигурации не означает Connected.
Windows-вариант запуска npx и доступность Chrome/Edge надо проверить на
конкретном ноутбуке; сейчас установки на Windows нет. Если npx не запускается
как stdio-процесс, установить сервер локально и указать node с путём к cli.js,
вместо попыток повторять неработающую команду. Не использовать профиль HeyGen.

Пример задания на собственном учебном/разрешённом сайте:
«Открой сайт, нажми кнопку заявки, проверь страницу назначения. Сохрани
URL кнопки, адрес ошибки и скриншот. Не отправляй форму и не покупай ничего».

Модель/подписка оплачиваются отдельно от открытого кода MCP. Само подключение
не создаёт ежедневную проверку. Регулярный запуск — отдельный исполнитель и
расписание. Для фиксированного маршрута обычный Playwright test/CLI может быть
проще и экономнее по токенам; MCP выбран для демонстрации действий по структуре
страницы и последующего диалогового управления, не как обязательный слой.

## Воспроизведение облачного smoke-теста

Установить @playwright/mcp@0.0.83 и SDK в отдельную папку зависимостей; Chrome
Headless Shell — через Playwright install chromium --only-shell. Затем:

```sh
node roman-reels/scripts/run-mcp-site-demo.mjs DEPENDENCY_ROOT BROWSER_EXECUTABLE OUTPUT_DIR
```

В текущем контейнере browser sandbox не работает; только для собственных
учебных страниц применён MCP_DEMO_NO_SANDBOX=true. На Windows не копировать
этот флаг по умолчанию. Кеши теста находятся в /workspace/scratch через
PLAYWRIGHT_BROWSERS_PATH и XDG_CACHE_HOME; не менялся HOME. Профиль isolated.

Версия 0.0.83 отдаёт большие snapshots в YAML-файлах. Драйвер читает только
файл внутри OUTPUT_DIR и передаёт browser_click параметр target из snapshot.
Старый параметр ref в этой версии не принимается. Проверяются фактические
HTTP статусы сервера и текст страницы после клика в обоих состояниях.
