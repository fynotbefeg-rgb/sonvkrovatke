## Новый общий адаптер `gemini-bounded-client.mjs`

- Без `allowGenerate === true`, ключа, разрешённой задачи и модели из явного списка — запрос не отправляется.
- Задачи только текстовой помощи: `draft_suggestion`, `summarize`, `classify`, `extract`, `critique`.
  Имена задач с утверждением, регистрацией, публикацией, производством, рендером или HeyGen отклоняются.
- Каждый запрос, включая повтор, сначала записывается в локальный журнал (`gemini-ledger.json`, вне Git).
  Значения по умолчанию: 1 запрос на запуск, 10 в сутки, 40 в неделю; журнал переживает перезапуск.
- Запрос до 16 000 символов, `maxOutputTokens` 4096, ответ до 256 КБ, тайм-аут 90 с.
- Повторов по умолчанию нет. Максимум 1 повтор и только для 429/503, при `Retry-After` не больше 60 с.
  `MAX_TOKENS`, блокировка, обрыв соединения и прочие коды не повторяются. Запасной модели нет.
- Ключ передаётся только в заголовке и вычищается из сообщений об ошибках.
- Результат всегда содержит `approvalAuthority`, `topicRegistration` и `productionAllowed` со значением false,
  а также `editorialReviewRequired: true`. Gemini не утверждает темы за Романа и не запускает производство.

Тесты: 8 офлайн-тестов на поддельном fetch (лимиты, перезапуск, повторы, обрезанный, заблокированный и
слишком большой ответ, утечка ключа).
Подключение к существующим скриптам (`run-researched-gemini.mjs`) — отдельный шаг с обычной редакторской
проверкой.

## Распределение работы для экономии недельного лимита Claude

| Работа | Исполнитель | Почему |
|---|---|---|
| Проверки хешей, форматов, квитанций, загрузка, Drive/Telegram-транспорт, супервизор, отчёты по журналам | обычные скрипты Node/Python + CI | детерминированно, бесплатно, уже покрыто тестами |
| Черновики хуков и основ, перефразирование, классификация тем по рубрикам, извлечение тезисов из сохранённых исследований | Gemini через адаптер (1 запрос за раз, бюджет в журнале) | дешёвая генерация текста; результат всегда `pending` |
| Разбор черновиков по `GEMINI_EDITORIAL_RULES` (фактические ошибки, обещания, тон) | сначала скриптовые проверки, затем короткая проверка Claude только по спорным пунктам | экономия лимита: Claude не переписывает весь текст |
| Архитектура, ревью кода, интеграции, расследование сбоев, живые операции на ноутбуке | Claude | нужны рассуждения и инструменты |
| Выбор и утверждение тем, текстов и хуков | **только Роман** (Google-таблица / бот) | ни Gemini, ни Claude не утверждают |
| Генерация аватара, монтаж, производство | не запускаются | отдельные разрешения владельца |

Практическое правило: сначала скрипт (0 токенов), затем Gemini для массового текста, Claude — только там,
где ошибка дорогая (безопасность, деньги, живые системы).

## Ключ

Для облака ничего делать не нужно: секрет `GEMINI_API_KEY` уже хранится в Actions.
Если Gemini понадобится на ноутбуке, ключ сохраняется только приватно (DPAPI CurrentUser, вне Git), по образцу
`setup-windows-telegram.ps1`. Такую форму сейчас не делаем — нет задачи, где она нужна.
Бесплатный уровень и квоты проекта не подтверждены (`freeTierAndBilling: unknown`): до проверки любой
генерационный запрос считать потенциально платным и выполнять только по отдельному разрешению.

## Исправления после ревью PR №44 (2026-10-13)
- Резервирование запроса (чтение журнала → проверка лимитов → запись) выполняется под эксклюзивным lock-файлом
  `gemini-ledger.json.lock`; устаревший lock (старше 2 минут) сообщается как `ledger_lock_stale`, а не снимается.
- Счётчик запусков занимается до ожидания, поэтому параллельные вызовы одного клиента не проходят оба.
- Временные файлы журнала уникальны для каждой записи (pid + UUID).
- Лимиты — только конечные целые в допустимых диапазонах, дневной не больше недельного; неизвестные ключи отклоняются.
- Схема журнала проверяется строго; повреждённый журнал не перезаписывается.
- Новые регрессии: три настоящих процесса Node одновременно при лимите 1 (ровно один запрос и одна запись), параллельные
  клиенты в одном процессе, недопустимые лимиты, повреждённые журналы. Тест гонки падает на прежней версии.
- Тесты зарегистрированы и в Windows-job CI.
