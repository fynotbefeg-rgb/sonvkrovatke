# Задание 01 для Claude Code: монтаж цельного MP4

Дата: 2026-10-10. Репозиторий `fynotbefeg-rgb/sonvkrovatke`, рабочая ветка **`automation/roman-reels-v1`**. Читай `docs/CODEX_HANDOFF.md`, `docs/MANUAL_HEYGEN_INTAKE.md`, `scripts/approval-manifest.mjs` и `scripts/plan-manual-intake.mjs` до изменений.

## Роли и цель этапа

Claude Code пишет код Remotion, монтажные шаблоны и GitHub Actions. Codex проверяет изменения, дорабатывает найденные ошибки и тестирует в репозитории. Gemini генерирует будущие сценарии. Цель HeyGen — автоматизация интерфейса через удалённый ноутбук, без API; worker ещё не настроен. Пользователь работает с iPhone. Общая цель: утверждение Романом сценария и хуков, запуск производства кнопкой Telegram-бота; см. `TELEGRAM_LAPTOP_PIPELINE.md`. Этот заказ реализует только монтажную часть общей цепочки.

Сделай отдельный Remotion-шаблон для **одного цельного видео аватара** (уже содержит хук и всю речь). Это первый этап обработки входящего видео, не включение автоматического производства. Не подставляй произвольный новый сценарий в существующий статический `RomanReel`.

## Текущее состояние

- `pv/src/Root.tsx` регистрирует старые композиции. `RomanReel.tsx` ожидает `h1/h2/h3` + `osnova`, темы/вставки заданы статически.
- Приёмщик `plan-manual-intake.mjs` сопоставляет утверждения и Drive-метаданные, вычисляет job_key и всегда выдаёт `render_allowed: false`. Он не скачивает и не обрабатывает видео.
- В Google `Сценарии!A5:K7` три новых пилота `R-knowledge-price-h1..h3`; на 2026-10-10 все pending, H–J пусты. Не создавай approval на их основе.
- Apps Script установлен пользователем дополнением, setup завершился успешно, deployment обновлён по сообщению пользователя. Реальное определение редактора Романа и отзыв утверждения ещё не подтверждены.
- Папка incoming и доступ производственного сервисного аккаунта к ней не подтверждены. Не используй вместо неё папку готовых работ.

## Реализовать

1. Добавь изолированный компонент в `pv/src/` и отдельную композицию в `Root.tsx`, сохраняя все существующие композиции и их параметры. Разрешение 1080×1920, частота кадров должна быть явной; длительность рассчитывай по проверенной длительности исходника, округляя вверх до кадра.
2. Вход: относительный путь цельного MP4 в `pv/public/rr/incoming/`, длительность в секундах, отображаемый хук, новые word timestamps `{word, start, end}`. Подпись хука — визуальный элемент; **не добавляй второй клип или повтор озвучки хука**.
3. Вход проверяй до расчёта длительности/рендера: конечная положительная длительность, непустые слова, конечные неотрицательные тайминги, `end > start`, порядок и отсутствие перекрытий, интервалы в границах исходника. Путь только локальный, без URL, абсолютных путей, `..` и управляющих символов. Некорректные данные завершают подготовку с понятной ошибкой.
4. Субтитры группируй в короткие читаемые блоки; активное слово соответствует текущему времени. Не обрезай длинное слово за экраном, не показывай текст до начала/после конца блока. Учитывай паузы, последнее слово, края кадра и безопасные поля для интерфейса Instagram.
5. Без исходника и таймингов показывай в Studio явное состояние «Нет проверенного исходника», не выдавай старое видео за новый ролик. На стороне команды подготовки отсутствующие/пустые данные должны блокировать производственное задание.
6. Сделай минимальный адаптер props и описание контракта. Метаданные задания должны связывать version_id/revision/script_hash/job_key/source file ID+MD5 с таймингами. Словарь `romanWords.json` для старых тем не изменять. Имена в props не доказывают утверждение или соответствие речи: перед будущим производством всё равно требуются проверка скачанных байтов, расшифровки и повторное чтение живого approval.

## Проверить

- Чистые проверки входа: NaN/Infinity/отрицательная длительность; пустые/обратные/перекрывающиеся/выходящие за видео тайминги; пути с обходом каталога или внешним URL; паузы и конец клипа; корректный путь и последовательность слов.
- Искусственный короткий fixture разрешён **только как наглядный тест компонента**, с отметкой `test_fixture`, без утверждения, без допуска к production, без подмены реальной расшифровки.
- Существующие тесты: `node roman-reels/scripts/apps-script.test.mjs`, `node roman-reels/scripts/manual-intake.test.mjs`, `node roman-reels/scripts/prepare-script-review.test.mjs`.
- Сборка Remotion bundle и проверка сохранения прежних composition IDs. `tsc --noEmit` ранее выявил восемь существующих ошибок в AiReel/FaceReel/FormulaReel2/FormulaReel3/LudiVideo; не скрывай их и не утверждай, что весь TypeScript проходит. Изменения не должны добавлять новых ошибок.

## Границы

Не менять `main`, не переписывать историю, не удалять файлы/старые композиции. Не запускать Apify, Gemini, HeyGen или другую оплачиваемую генерацию. Не записывать статус approval, не отправлять сценарии и не менять общий Apps Script. Не включать cron/автопубликацию/авторендер, не снимать блокировки приёмщика.

Не использовать `prep_topic.py --fake` или интерполяцию вместо реальных таймингов. Не скачивать неизвестные MP4. Не переносить секреты в код/логи. Не считать этот этап готовым циклом из 90 роликов.

Если меняешь Actions, делай только изолированную offline-проверку по ручному запросу. Новые branch-only workflow могут не быть зарегистрированы на default branch; не переносить их в main ради запуска. Зарегистрированный `roman-reels-check.yml` уже имеет отдельные режимы; не запускать его платный `collect_one_apify_reel`.
