# Связь простой таблицы с утверждением основы и хуков

2026-10-11. Код подготовлен и проверен локально; в действующий Apps Script
НЕ установлен. Таблица и решения Романа не изменены. Новых секретов, платных
сервисов, сообщений, генерации аватара и рендера нет.

## Что реализовано

`apps-script/SharedReview.gs` дополняет существующий Code.gs/RomanApproval.gs.
Модуль выключен по умолчанию. Существующий endpoint сохраняет POST/token,
`get_production_queue` и legacy manifest/scriptHash. Только серверное событие
Google `e.user.getEmail()` из разрешённого списка может создать квитанцию.
Владелец installable trigger не подставляется вместо редактора. Пустая или
скрытая Google личность означает отсутствие утверждения, даже если dropdown
показывает «Утверждено». Неподтверждённое значение после такого события
очищается, чтобы не показывать ложный допуск. Реальная доступность e.user для аккаунта Романа ещё
не проверена; при отсутствии личности выбрать отдельный подтверждённый канал,
не ослаблять проверку и не ставить email вручную.

Опция `ROMAN_SHARED_REVIEW_ENABLED=true` разрешает регистрацию и новые
утверждения. Установка файлов сама её не включает. Отключение опции после
регистрации останавливает новые managed темы и не возвращает прежние canonical
утверждения для этих тем. Legacy темы без регистрации сохраняют старый путь.

## Предлагаемый вид — четыре строки, семь прежних столбцов

Этот вид ещё не внесён в живую таблицу. Добавление основы требует одной
строки к прежнему трёхстрочному блоку; новые технические столбцы не добавляем.

| Строка | A/B | C/D |
| --- | --- | --- |
| первая | тема / решение по теме | точная общая основа / решение по основе |
| вторая | пусто (относится к теме выше) | хук 1 / решение по хуку 1 |
| третья | пусто | хук 2 / решение по хуку 2 |
| четвёртая | пусто | хук 3 / решение по хуку 3 |

E/F/G сохраняются для анализа, статистики и ссылки. В первой версии они
пусты при регистрации и заполняются исследованием отдельно. Их изменение
не отзывает решение по речи. A/B не объединяются новым модулем. Ни одна
существующая строка не удаляется/не перезаписывается: новый пакет добавляется
ниже последней заполненной строки, старая редакция сохраняется как история.

Если пакет содержит Instagram/TikTok окончания, их точные тексты видны в C
вместе с основой; D утверждает весь показанный блок. Это не автоматический
перенос прежнего утверждения окончания. TikTok окончание требует личного
сообщения, а не комментария. Пакет без окончаний даёт три версии, с двумя
окончаниями — шесть платформенных версий; это не команда массовой генерации.

## Контракт и блокировки

JSON Schema: `schemas/shared-review-v1.schema.json`. Packet v1 содержит ровно
schemaVersion, topicId, topicText, revision, bodyText, hooks[3], endings[0|2].
Дополнительно сервер проверяет уникальные номера/тексты хуков, разные площадки,
TikTok CTA и лимит сериализованного пакета 8000 UTF-8 байт. В квитанции нет
пользовательского права установить approved_by/approvalGranted.

Стабильная привязка topicId/revision/sheetId/firstRow/packetHash хранится в
Script Properties сервера. Хук связан с точной основой и окончаниями. Очередь
каждый раз перечитывает текст, решения и квитанции; доверять одному dropdown
или кэшу запрещено. Формулы в области A:D, перенесённые строки, несовпадающий
текст, отозванный разрешённый email или отсутствие квитанции блокируют запуск.
Изменение текста без новой регистрации консервативно блокирует весь пакет.
Новая зарегистрированная редакция требует большего revision и новых решений.

Отказ по основе/теме блокирует все варианты. Отказ по одному хуку блокирует
только его варианты. Bulk paste решений не выдаёт утверждения. Анализ/ссылка
не являются утверждением. Managed тема не может обойти отказ через старую
скрытую вкладку «Сценарии». Успешное утверждение не запускает производство:
оно даёт совместимый manifest для существующей очереди, а отдельная кнопка
снова читает актуальное состояние перед созданием задания.

`script_text` сохраняет точные байты `hook + "\n\n" + body [+ "\n\n" + ending]`.
`script_hash` сохраняет старую семантику [version_id, revision, hook, full speech].
Распознавание речи и проверка реальных MP4 остаются отдельными этапами. Модуль
не делает ProductionQueue облачным сервером и не включает настоящий Telegram.

## Подготовка из текущих черновиков без сети

```bash
node roman-reels/scripts/prepare-shared-review.mjs \
  roman-reels/research/site-technical-seo/reviewed-revision6.json \
  ai-seo-audit 'SEO-проверка сайта' /tmp/new-shared-review-v6.json
```

Выходной файл должен отсутствовать. Команда проверяет ревизии, исходную основу,
все три точных полных текста и старые хеши. Для текущей v6 файл проверен с JSON
Schema локально. Он не зарегистрирован и не утверждён; editorialReview v6
остаётся pending. Не регистрировать рабочий пакет до редакторской проверки и
показа согласованной точной речи Роману.

1. Подтвердить Apps Script проект 1XxdsdAGLMf1IY15812fwW5EQp6MJoCgDm7J96H10h0xk_Hykd_utvnd1,
   сохранить исходный код/номера deployments/trigger handlers в защищённый
   локальный backup; не коммитить значения Script Properties.
2. Установить SharedReview.gs и обновить существующий вариант обработчика:
   либо Code.gs, либо RomanApproval.gs. Не устанавливать оба. При addon
   сохранить legacy код и единственный глобальный doPost/onRomanApprovalEdit.
3. Проверить, что опция выключена, legacy GET защищён, старый authenticated
   read-only queue работает. Сохранить текущий URL и обновить существующее
   deployment новой версией; не подменять URL до проверки клиентов.
4. После согласования четырёхстрочного вида и проверки кода включить опцию.
   Зарегистрировать отдельный учебный пакет через существующий защищённый
   POST action `add_shared_review` с полем packet. Token передаётся только в
   защищённом запросе; нигде не выводится. Это не выдаёт утверждения.
5. Проверить личное событие Романа и read-only queue, отказ по основе/хуку,
   отзыв email, новую редакцию и старую кнопку. Производство/Generate не запускать.
6. Только после успешного учебного теста подключать рабочий пакет. Файлы
   пользователя, старые решения и main не удалять/не переписывать.

При неоднозначном результате регистрации сначала прочитать существующую
привязку/строки, не повторять POST вслепую. Одинаковый зарегистрированный пакет
повторно не добавляет строки. Неполная/изменённая регистрация блокирует повтор
и требует диагностики; автоматическая очистка истории не предусмотрена.
