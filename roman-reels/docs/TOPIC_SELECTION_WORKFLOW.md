# Выбор тем до генерации сценариев

Требование Романа, переданное владельцем проекта 2026-10-10.
Это описание целевого порядка и задание на реализацию; новые автоматические
проверки утверждения тем пока не подключены к производственному конвейеру.

## Порядок работы

1. Подготовить банк тем о практическом использовании ИИ предпринимателями.
   Для каждой темы показать бизнес-задачу, анализ и внешний успешный ролик.
2. Роман выбирает темы: «Выбрана», «На доработку» или «Не подходит».
   Выбранные темы можно распределять по будущим месяцам.
3. Только для выбранных тем создавать одну общую основу и три отдельных хука.
4. Роман утверждает актуальные тексты основы и хуков. Выбор темы сам по себе
   не утверждает сценарий и не разрешает генерацию видео.
5. Кнопка Telegram запускает постановку разрешённых заданий в очередь после
   повторной проверки утверждений, версий и хешей. Изменение основы требует
   повторного утверждения всех затронутых вариантов.

## Представление банка тем

Предлагаемая отдельная вкладка «Темы и примеры», с одной строкой на тему:

| Поле | Назначение |
| --- | --- |
| ID темы | Стабильная связь с тремя будущими роликами |
| Тема и бизнес-задача | Например, обработка заявок, продажи, документы, аналитика |
| Целевая аудитория | Кому полезно и при каких условиях |
| Польза и ограничения | Что можно показать и что ещё требует проверки |
| Внешний пример | Прямая ссылка на конкретный ролик, автор, платформа |
| Статистика | Просмотры, лайки, комментарии; неизвестное явно отмечать |
| Источник и дата проверки | Отдельно дата считывания и дата снимка метрик, если известна |
| Анализ | Хук, бизнес-польза, структура; монтаж описывать только после просмотра |
| Статус проверки примера | Просмотрен / доступны только метрики / недоступен |
| Решение Романа | Выбрана / На доработку / Не подходит / На рассмотрении |
| Комментарий и месяц | Причина решения и планирование будущих выпусков |

Высокие просмотры сами по себе не доказывают бизнес-пользу. Нельзя выдавать
метрики другого ролика или аккаунта за метрики конкретного примера. Ролики
с недоступным содержанием остаются кандидатами, а не проверенными референсами.
Сценарии не копировать: создавать собственную подачу и проверять утверждения.

## Критерии следующей реализации

- Сохранить существующую таблицу сценариев и решения Романа без миграции вслепую.
- Отдельно хранить решение о теме и решение о точном тексте.
- Проверять выбор темы до запуска генерации; повторный запуск не создаёт дубликаты.
- Изменение описания выбранной темы фиксировать версией и возвращать на проверку,
  если оно меняет согласованный смысл.
- Платный сбор данных и генерация остаются под действующими бюджетными разрешениями.
- Сначала заполнить небольшую проверенную подборку, а не 30 тем с вымышленными
  примерами или отсутствующими метриками. Затем расширять банк до месячного плана.

Утверждение отдельных компонентов и связь с Telegram требуют согласованного
расширения текущего контракта; этот документ не заменяет существующие проверки.
