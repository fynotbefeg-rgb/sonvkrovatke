# Roman Reels — автоматизация после утверждения сценариев

Статус: проектный контракт, не включён в production. Единственное плановое ручное действие — утверждение сценариев Романом.

## Цель
30 тем × 3 хука = 90 вертикальных MP4 за месяц. Для каждой версии сохраняются индивидуальные текст, аватарный дубль и итоговый ролик. Не заменять существующий Remotion-монтаж примитивной склейкой.

## Состояния каждой версии
`draft → pending_approval → approved → avatar_queued → avatar_ready → assets_ready → rendering → quality_check → delivered`

Альтернативные состояния: `rejected`, `failed_retryable`, `failed_blocked`. Никакого перехода к HeyGen до `approved`.

## Источник правды
Один реестр версий с полями:
- `topic_id`, `hook_id` (1–3), `version_id`, `script_revision`
- `hook_text`, `script_text`, `approval_status`, `approved_at`, `approved_by`
- `script_hash`, `avatar_job_id`, `avatar_asset_url`, `render_job_id`, `output_file_id`, `status`, `last_error`

Изменение текста после утверждения сбрасывает статус в `pending_approval`. Дедупликация по `version_id + script_hash`. Нельзя повторно создавать уже готовое видео при повторном событии.

## Этапы внедрения
1. **Контракт утверждения.** Выбрать интерфейс Романа (например, Google Sheets с защищёнными колонками или простую веб-страницу). Утверждение привязывать к точной редакции текста; фиксировать кто и когда утвердил. Тест: неутверждённые сценарии не попадают в генерацию.
2. **HeyGen API.** Проверить план, API-доступ, разрешения на конкретный аватар/голос, лимиты и стоимость. Сделать отдельный адаптер создания задачи и получения результата с polling/webhook, тайм-аутами, повторами и сохранением исходного MP4. Не подменять ручную генерацию API, пока не проверена совместимость.
3. **Монтаж.** Параметризовать текущие Remotion-композиции новыми сценариями/ассетами; сохранить субтитры, оверлеи, B-roll, 1080×1920, 25fps и качество CRF18. Проверять длительность, наличие аудио и видео, вертикальный размер, не пустой файл.
4. **Пакетная очередь.** Ограниченная параллельность, бюджетные лимиты, идемпотентные повторы, запуск по событиям утверждения и дозапуск после сбоя. GitHub Actions не использовать как бесконечно работающий сервер; длительные HeyGen-задания хранить в реестре и проверять отдельными запусками.
5. **Доставка и мониторинг.** Загружать только прошедшие проверки MP4 в папку Романа на Drive. Хранить идентификатор загруженного файла, исключать дубли, уведомлять о сбоях. Продлить OAuth-доступ для длительной работы: Google OAuth External/Testing с drive.file может давать refresh token на 7 дней; проверить Production и требования Google до боевого запуска.

## Безопасность и границы
- Никогда не записывать API-ключи, OAuth-токены или rclone.conf в репозиторий и логи. Только GitHub Secrets / защищённый менеджер секретов.
- Роман утверждает финальный текст, а не только тему. Отредактированный текст требует повторного утверждения.
- Автопубликация в соцсети НЕ входит в текущий контракт: результат — MP4 на Google Drive.
- Не включать массовый HeyGen-рендер до оценки бюджета и успешного end-to-end теста одного сценария.
- Ветка реализации: `automation/roman-reels-v1`; `main` не изменять.

## Критерий готовности
Один сценарий утверждён Романом → без ручных промежуточных действий получен HeyGen MP4 → Remotion сохранил исходный стиль → итоговый файл проверен и находится на Google Drive. Затем тест трёх хуков и пакет из 30 тем.
