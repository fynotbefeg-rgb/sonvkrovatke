# Gemini: проверенное исследование → новая речь

Статус: подготовлен отдельный режим для одной SEO-темы. Новая речь Gemini
ещё не получена; учебное демо не выдается за клиентский кейс.

## Материалы и запрос

research/gemini-revision-seo/search-console-demo.json — три учебные строки.
prepare-seo-research-demo.mjs вычисляет CTR и применяет явно указанный
иллюстративный критерий: показы >=1000, позиция <=10, CTR <=2%. Не универсальная
SEO-норма. demo-result.json содержит результат и SHA256 входа: CRM, 1200 показов,
12 кликов, CTR 1%, позиция 4.8. Нет измеренного роста или проверки причины.

brief-v2.json содержит замечания Романа, бизнес-задачу, первичные источники
из предыдущей проверки, сравнение способов, демо и ограничения. Популярность
референса отдельно: просмотры не равны охвату, а комментарии не равны продажам.

run-researched-gemini.mjs prepare создаёт точный запрос без API.
Режим generate использует существующий GEMINI_API_KEY и требует явного
ROMAN_GEMINI_ALLOW_GENERATE=true. После неудачной первой попытки модель следующего запроса — gemini-3-flash-preview;
перед генерацией GET проверяет каталог, не выбирает другие модели молча.
Максимум один generateContent POST, вход <=16000 символов, выход <=4096
токенов, таймаут 90s, без автоматических повторов/переходов на другую модель.
Таймаут не доказывает, что Google не обработал запрос; сначала проверить запуск,
не повторять автоматически. Фактическая стоимость/остаток бесплатного лимита
не установлены. usageMetadata сохраняется в результате, не превращается в цену.

## Результат и утверждение

Одна общая основа и три разных хука; script_revision=2, body_revision=2.
version_id сохраняет существующий контракт, approval hash меняется с revision.
Новый результат pending_approval, productionReady=false, editorialReviewRequired=true.
Проверяются структура, длина, ссылки на переданные источники и явное упоминание
учебного примера. Это НЕ автоматическая проверка смысла/правдивости текста:
Codex должен сопоставить каждое утверждение с источниками и демо перед показом.

Этот режим сохраняет артефакт для проверки и не обновляет Sheets/Google Doc,
не утверждает текст, не делает HeyGen/рендер и не заменяет отклонённую revision 1
в incoming. Далее нужно согласовать точную основу/хуки и соответствие окончаний,
собрать 6 платформенных полных вариантов с revision 2, затем провести утверждение.
Окончания не наследуют разрешение на изменённую полную речь.

## GitHub Actions

Существующий roman-gemini-smoke.yml на feature/codex-pipeline получил режимы:
prepare_research (по умолчанию), generate_research, legacy_smoke.
Первый проверяет ключ/модель через GET и формирует offline preview.
Для generate_research нужно allow_generation=true после разрешения владельца.
Legacy-путь сохранён, тоже требует явного allow_generation; только он сохраняет
прежнюю отправку тестов в Sheets. Не использовать legacy для новой revision 2:
старый импорт пропускает уже существующие version_id и не реализует их обновление.
Main не меняется. Новое расписание Drive не вызывает Gemini.

Проверки researched-gemini-drafts.test.mjs: 5 сценариев, включая учебный расчёт,
неполное исследование, новые approval hashes, неизвестные источники,
отсутствие раскрытия учебного примера и ошибку API без второго POST.
