# Apify: подключение к проекту

Роман предоставил пользователю API-токен Apify, сохранённый пользователем в GitHub Secrets. Значение токена не передано в рабочее окружение Codex. Доступ проверен через Actions, но Apify вернул HTTP 401. Конкретный Actor/Dataset и задача сбора пока неизвестны. Нельзя считать этот токен доказательством API-доступа HeyGen.

## Последняя проверка — 2026-10-09

Пользователь сообщил, что сохранил `APIFY_TOKEN` в GitHub Secrets. Codex запустил `roman-reels-check.yml` с `check_apify_access=true` в рабочей ветке: run [37973225979](https://github.com/fynotbefeg-rgb/sonvkrovatke/actions/runs/37973225979), commit `176ce636dacf813f2534c8b2bb0284d66f40cd79`. Четыре теста прошли на Node 22. Секрет поступил в runner (значение скрыто), но `GET /v2/users/me` вернул **401 Unauthorized**. Доступ Apify пока не подтверждён; нужны проверка/замена значения секрета самим пользователем и повторный read-only запуск. Никакие Actors не запускались, Remotion job пропущен. Codex не читал значение токена.

Подготовлены `scripts/check-apify-access.mjs` и ручной workflow `roman-apify-check.yml`. Проверка делает только `GET https://api.apify.com/v2/users/me` с Bearer-токеном. Токен не включается в URL, логи, репозиторий или artifacts. Actor/task run endpoints не вызываются. Редиректы запрещены, время запроса ограничено 30 секундами. В ответе не публикуются данные аккаунта, сообщения сервера или баланс.

## Настройка с iPhone

1. В существующем репозитории открыть Settings → Secrets and variables → Actions → New repository secret.
2. Имя секрета: `APIFY_TOKEN`. Значение: токен, полученный от Романа. Не присылать токен в переписку и не добавлять его в файлы проекта.
3. После сохранения запустить уже зарегистрированный workflow `roman-reels-check.yml` в ветке `automation/roman-reels-v1` с `check_apify_access=true`. В этом режиме job Remotion пропускается, выполняются только тесты и чтение аккаунта Apify. Новый отдельный `roman-apify-check.yml` не зарегистрирован, поскольку отсутствует в default branch; ради его регистрации `main` не менялась. GitHub Actions secret доступен только runner, не рабочему окружению Codex. Для этого workflow не требуется устанавливать ключ в окружение Codex.
4. Если доступ подтверждён, определить конкретный Actor/Dataset, источники (например, публичные примеры Reels) и схему данных. Сначала читать уже готовые результаты; запуск сбора и расходы согласовать отдельно.

Apify планируется как источник тем/примеров до Gemini и утверждения, а не как автоматическое подтверждение фактов или производство аватара. Утверждённые сценарии и готовые MP4 не перезаписывать результатами сбора. Не подключать произвольный Actor только на основании наличия токена.

Текущее восстановление Apps Script: пользователь снял маркеры комментария вокруг старого кода, функции снова появились. Подготовленное обновление `apps-script/Code.gs` не установлено; схема доверенного утверждения остаётся отдельным незавершённым этапом. Не запускать производство на старой очереди только потому, что Apify подключён.

Проверка без сети: `node roman-reels/scripts/apify-access.test.mjs`. Четыре теста проверяют единственный GET, отсутствие запросов без токена, обработку ошибок без утечки и отказ при неверном формате ответа.
