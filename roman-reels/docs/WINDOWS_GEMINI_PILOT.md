## Что подготовлено

- `setup-windows-gemini.ps1`: локальная форма с замаскированным полем API key,
  названием проекта и подтверждением владельца, что Free относится именно к нему.
  Ключ шифруется DPAPI CurrentUser в `%LOCALAPPDATA%\RomanReels\gemini\config.dpapi`.
  Существующий конфиг не перезаписывается, сеть/автозапуск/системные переменные не меняются.
- `run-windows-gemini.mjs`: команды `init-store`, `check-config`, `check-access`,
  `prepare`, `generate`. Ключ передаётся редакторскому коду в памяти, без аргументов
  командной строки, установки process/user env или извлечения GitHub credentials.
- Один постоянный журнал `gemini-ledger.json` рядом с DPAPI-конфигом. Инициализация
  не сбрасывает счётчики. Чужой marker и повреждённый журнал блокируют работу.
  Реальный путь проверяется вне Git/временной папки. Автозапуска Gemini нет.
- Прежний bounded client: одна генерация за запуск, максимум10/сутки и40 за7дней,
  без повторов/запасной модели. Все helper-процессы ноутбука используют один путь.
  Другие клиенты/ключи/ручные запросы вне этого wrapper в его бюджет не входят.

## После разрешённого слияния — задание Claude

1. Обновить основной клон только fast-forward. Не трогать бот, задачи планировщика,
   Google-согласования, Drive и прочие MCP. Не выводить конфиги/окружение/ключи.
2. Открыть локальную форму:

```powershell
powershell.exe -NoProfile -STA -File .\scripts\setup-windows-gemini.ps1
```

Рабочая папка — `roman-reels`. Единственное действие владельца: в этой форме
вставить свой ключ, проверить проект/Free, нажать Save. Ключ не вводить в чат
Claude/Codex/Telegram, в терминальную команду или файл репозитория. Значения формы
не читать инструментами и не снимать экран с открытым ключом. Скрипт сам буфер
обмена не читает и не очищает, чтобы не затронуть чужие данные.

3. После сохранения:

```powershell
node scripts/run-windows-gemini.mjs init-store
node scripts/run-windows-gemini.mjs check-config
node scripts/run-windows-gemini.mjs check-access
```

Последняя команда делает каталог моделей и countTokens для короткого стандартного
текста, **не generateContent**. Она не доказывает тариф и не даёт права генерации.
Ключ/проект в ответе провайдера не публиковать. В отчёте — только HTTP-статусы,
modelListed, generationCalls и наличие приватной настройки/журнала.

Если Google отказывает из-за региона, квоты, модели или ключа — остановиться;
без повторов, смены модели/аккаунта, VPN/прокси или платного fallback в этой задаче.
Модель в существующем CLI закреплена: gemini-3-flash-preview. Наличие ключа Free
не доказывает доступность этой модели для данного проекта.

## Одна генерация — отдельное разрешение, пока не выполнять

Результат только pending, никакого выбора темы/утверждения за Романа. До отдельного
разрешения можно использовать `prepare brief.json output.json` без ключа и сети.
Уже принятые основу/хуки не перегенерировать. Для первого пилота выбрать отдельное
учебное задание и точный проверенный brief, не публиковать клиентские данные в модель
без разрешения владельца. Модельный ответ требует обычного редакторского контроля.

`generate` требует одновременно `--allow-one-generation` и process-only
`ROMAN_GEMINI_ALLOW_GENERATE=true`. Постоянную переменную/флаг не сохранять.
Дневной/недельный бюджет — число запросов, не гарантия бесплатности и не денежный cap.
При неоднозначном сетевом исходе запрос уже учитывается; автоматически не повторять.
