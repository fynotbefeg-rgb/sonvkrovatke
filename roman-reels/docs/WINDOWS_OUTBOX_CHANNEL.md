# Канал outbox моста → облачный издатель — кандидат

2026-10-13. Код и 7 офлайн-тестов. Живой Drive, workflow, бот и Google не менялись.

Путь: мост на ноутбуке (`queue-delivery-bridge.mjs`) → локальный outbox → **закреплённый слот Drive
`source-plan-outbox-v1.json`** (рядом с почтовым ящиком в `_windows-jobs`, создаётся владельцем, пустое
содержимое `{"outboxVersion":"1.0.0","status":"empty"}`) → сериализованный облачный издатель → почтовый ящик.
Ноутбук никогда не пишет почтовый ящик: единственным его писателем остаётся облако.

## Windows: `pushOutbox`
- Берёт самый новый неистёкший конверт из локального outbox (файлы не удаляются).
- Проверяет ID/имя/MIME/родителя/размер/MD5 слота; слот не может совпадать с ящиком или папкой.
- Одинаковые байты → `already_sent`, без записи. Пустой слот, продление того же плана, истёкший
  (никогда не опубликованный) конверт или конверт, уже переложенный облаком в ящик, можно заменить.
  Другой живой неопубликованный конверт → `blocked_unconsumed`, без записи.
- Запись PATCH по ID, затем проверка метаданных и readback. Потерянный ответ разрешается чтением слота.

## Облако: `relayDecision` (чистая функция)
- Пустой слот → `nothing_to_relay`; истёкший → `outbox_expired`.
- Каждый вариант пакета должен совпадать с утверждённым вариантом из **свежего аутентифицированного чтения
  очереди** (тема, хук, ревизия, тексты, хеш). Иначе `approval_changed_or_revoked`.
- Те же байты уже в ящике → `already_published`. Затем проверка подтверждения `mayReplaceDelivery`:
  другой неподтверждённый пакет → `blocked / previous_not_acknowledged`.
- Только `publish` разрешает вызвать существующий `publish-windows-plan.py` с байтами из слота.

## Исправления после ревью PR №43 (2026-10-13)
- `relayDecision` принимает очередь только как объект, возвращённый `readApprovedQueue` в этом же процессе, неизменённый и
  не старше 5 минут (`assertFreshAuthenticatedQueue` в `approved-four-part-jobs.mjs`). Сохранённый, скопированный или
  изменённый JSON отклоняется, даже если в нём `approved`. Каждый вариант должен иметь `approved_by` и прошедший `approved_at`.
- Почтовый ящик в релее и на Windows проверяется целиком: точный пустой маркер или полный конверт.
- Слот outbox считается «переложенным облаком» только если закреплённый ящик (ID, имя, MIME, родитель, размер, MD5)
  содержит **точно те же байты**. Подделка `{status, deliveryId}`, продлённый конверт с тем же ID или перемещённый ящик
  перезапись не открывают.
- Новые регрессии: подделанная/скопированная/устаревшая/изменённая очередь, подделанный и неполный ящик (без записи в Drive).
  Канал outbox: 9/9; планировщик 7/8 (Python-сверка только в CI), мост 7/7, подтверждения 9/9, приём 10/10.
