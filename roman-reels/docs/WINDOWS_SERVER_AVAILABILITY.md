# Claude: доступность Windows-ноутбука без человека рядом

Цель — сохранить рабочую сессию для будущего исполнителя HeyGen, пока Роман выбирает тему. Это отдельная проверка, не установка генерации/новых инструментов. Сейчас сайт/Apps Script можно обслуживать в облаке независимо от ноутбука.

В актуальном существующем клоне прочитать WINDOWS_SETUP.md и этот документ через git show origin/feature/codex-pipeline, не делать reset/clean/force. Системные команды — только чтение:

1. Проверить, подключён ли ноутбук к сети питания, какая схема электропитания активна и значения таймеров sleep/hibernate/закрытия крышки для AC и battery. Windows powercfg /getactivescheme и /query можно применять без изменения настроек. Не публиковать полный вывод с личными путями/аккаунтами.
2. Проверить состояния служб Chrome Remote Desktop и уже установленного RustDesk, наличие текущей интерактивной Windows-сессии и фактических playwright-google/старого playwright инструментов Claude. Не извлекать пароли, tokens/cookies, не менять режим браузеров и не входить в HeyGen/Google.
3. Установить по наблюдениям, мешает ли sleep/reboot unattended работе; не объявлять службу с автозапуском доказательством сохранения авторизованного браузера после reboot. Не перезагружать и не выходить из Windows, не закрывать крышку и не убивать процессы для теста: это может оборвать текущий доступ без человека рядом.
4. Если настройки мешают серверному режиму, подготовить конкретные обратимые команды только для режима AC с исходными значениями и откатом. Пока не применять. Не менять политики Windows Update, UAC, защиту, firewall/порты, аккумуляторные настройки и не включать Windows auto-login. Монитор может выключаться без сна системы.

Безопасный отчёт: roman-reels/docs/WINDOWS_SERVER_AVAILABILITY_RESULT.md в отдельной ветке feature/windows-server-availability-20261012 и PR в feature/codex-pipeline, без main/слияния/reviewers. На телефон максимум четыре строки: доступность, PR, конкретный блокер и одно действие при необходимости. Длинный отчёт в Git; выводы только по реальным наблюдениям. Публичные отчёты не содержат имён Windows пользователя, desktop ID, паролей, IP/VPN IDs или снимков почты.

Это не новый монтажный проект, не бесплатный тариф коммерческой VPN и не обход ограничений сервиса. Не подключать платные услуги, не использовать публичный RustDesk для чувствительных действий, существующий работающий Chrome Remote Desktop сохранить.
