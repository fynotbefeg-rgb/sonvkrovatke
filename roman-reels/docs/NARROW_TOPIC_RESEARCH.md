# Узкое исследование после выбора темы

2026-10-12. Первый компонент работает офлайн; это не подключённый автоматический поиск после изменения таблицы.

## Что реализовано

scripts/topic-reference-plan.mjs получает точный scope темы и сохранённую metadata-выгрузку. Связывает результат с topicId, topicRevision, title/формулировкой процесса и хешами входов. Для каждого ролика проверяет чистую прямую ссылку и ID/автора, дату, свежесть счётчиков, достаточное число просмотров/воспроизведений, совпадение с каждой группой узких терминов. Лайки, комментарии и уникальный охват не подменяют просмотры. Неподходящие записи получают причины отказа. Конфликтующие дубликаты останавливают обработку; идентичные учитываются один раз.

Рабочие пороги: публикация <=60 дней, счётчики <=7 дней, views или plays >=100000. Это предварительный фильтр данных Apify, а не подтверждение первичных счётчиков или редакторское решение. Метаданные датасета не доказывают, что ролик просмотрен.

Совпадение терминов — детерминированная предварительная проверка подписи, а не смысловой анализ видео. Термины коротких AI/SEO не совпадают с кусочками слов email/прочего текста. Есть ложные отрицания: если нужный смысл звучит только в видео, подпись может не пройти фильтр. Поэтому отсутствие кандидатов в выгрузке не доказывает отсутствие подходящих роликов на площадке. Популярность ролика не гарантирует успех нашей версии.

Выход содержит предварительно ранжированных кандидатов, причины отказа, до двух предложенных прямых ссылок для detail-сбора и RU/EN запросы по теме для площадок. Это предложения, не исполняемый Actor payload: текущий проверенный collector поддерживает заданные профили/прямые Reel URL, а keyword discovery ещё не подключён. TikTok/YouTube адаптеры также отсутствуют.

Всегда false: networkExecutionAllowed, geminiGenerationAllowed, eligibleForRomanReview, romanApprovalGranted, productionReady. Никаких API/Google/HeyGen/model-вызовов, утверждений или списаний. jobKey помогает связать одинаковые входы, но не является уже развёрнутой очередью/lease или защитой от оплаченного повторного запуска.

## Что требуется для подключения живого выбора темы

1. Отдельный свежий аутентифицированный снимок решения Романа по точной теме/версии. Существующий production endpoint выдаёт утверждённую речь после основы/хуков; он не является topic-only очередью. Текст «Утверждено» из произвольного JSON не является доверенным решением.
2. Topic-only регистрация до генерации основы/хуков: текущий shared packet требует их наличия. Нужно спроектировать совместимый read/approval adapter без новых видимых технических столбцов и без превращения выбора темы в утверждение речи. Его живое внедрение — отдельное согласование/деплой. Старые approved-решения не переносить без привязки к тексту.
3. Проверенный discovery adapter по узким запросам: подтверждённая официальная схема Actor, тариф/лимит и допустимый источник. Не выдавать profile feed за поиск по всем Reels и не подставлять keyword-поля в старый Actor без проверки.
4. Сохраняемая очередь/журнал, бюджет и повторная проверка актуальности выбора перед реальным платным запуском. Ограниченный согласованный тест, не массовый сбор.
5. Просмотр видео/речи, подтверждение счётчиков и конкретного процесса, собственный тест бесплатного пути, редакторская проверка. Лишь затем данные могут стать брифом Gemini; после генерации точный текст и хуки снова утверждает Роман. Связка с существующим editorial-release gate обязательна.
