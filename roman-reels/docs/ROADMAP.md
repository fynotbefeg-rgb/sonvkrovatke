# Roman Reels Factory — дорожная карта ТЗ 3.0

Основная цель: 30 тем × 3 хука = 90 самостоятельных профессиональных видео/месяц.
Текущий статус: отдельные проверенные компоненты, не готовая фабрика. См. [аудит](AUDIT_V3.md).

## P0 — аудит и разделение (этот PR)

Подготовлены задания Codex/Claude, проект schema/validator, Windows/HeyGen архитектура.
Существующие production paths не переписаны; contract и cloud storage ещё не внедрены.
Согласование владельцем: контракт 1.0.0 с сохранением старого approval hash и P1 ниже.
Постоянный hosting очереди выбирать отдельно, с конкретной стоимостью и миграцией.

## P1 — один автоматически смонтированный существующий MP4, без Windows

1. Codex: `pv/public/ai/body1.mp4` как development fixture; источник уже прошёл ffprobe/decode.
   Получить свежие реальные слова/сегменты CPU-транскрипцией, сопоставить с услышанным текстом,
   измерить ресурсную стоимость; не подставлять fake timestamps или старый script.
2. Claude C0–C2: устранить TypeScript ошибки, реализовать Director и универсальную композицию
   на существующей базе. Детерминированные смысловые правила допустимы для первого этапа.
3. Codex: вход/schema/семантические проверки → Director → Remotion CLI → полный decode/QC.
4. Artifact: MP4 1080×1920 с речью, word-highlight subtitles, осмысленным визуальным акцентом,
   JSON и контрольными кадрами. Просмотр владельцем перед дальнейшей разработкой качества.

Готовность P1: повторяемая команда по реальному source+timings, schema tests, render/QC и stills.
Это НЕ production публикация: старый body-клип не доказан как текущий утверждённый сценарий с хуком;
finished Drive/Sheets «готово» не меняются. Для production-pilot требуется точный approved snapshot
и совпадающий новый source. Зависимость от Claude отмечается честно, если сеанс ещё не подключён.
Загрузка модели и compute оцениваются перед запуском; платные сервисы не запускаются автоматически.

## P2 — облачный производственный пилот

Проверить реальное approval/revocation Романа; добавить Drive watcher/download, постоянную очередь
и Telegram start-button transport после согласования hosting. Telegram запускает, Sheets утверждает.
Сначала manual MP4 с точной версией/hash, затем speech→montage→render→QC→Drive→Sheet для одного заказа.
Тесты: stale edits, source mismatch, две доставки, retries, crash/restart, duplicate upload,
failed QC→не готов. Новый cloud backend пока не выбран и не создан.

## P4 — Windows и разрешённая HeyGen UI автоматизация

Подготовка mock-компонентов возможна сейчас. Реальный UI blocked до проверки разрешения и настройки
ноутбука. Следовать WINDOWS_SETUP и HEYGEN_BROWSER_AUTOMATION. Один bounded test, один worker,
без API, без обхода защиты; ambiguous submit — ручное разрешение, не повторный Generate.
Если схема запрещена, зафиксировать препятствие целевой архитектуре; manual intake сохраняется.

## P5 — полная цепочка и постепенное масштабирование

Один актуальный approved script → Windows/HeyGen → Drive → speech → Director → Remotion →
QC → finished Drive → Sheets. Затем несколько последовательных роликов, измерение времени,
лимитов, стоимости, ошибок и качества. Только после результатов — план 90/месяц.
Ноутбук offline приостанавливает HeyGen, не облачные этапы; годность масштаба пока не доказана.
