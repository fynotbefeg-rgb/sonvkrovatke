# Windows: обновить клон и выполнить локальный SEO-опыт

Задание после WINDOWS_FIRST_CHECK.md и полученного WINDOWS_READINESS_REPORT.md. Владелец разрешил продолжать настройку проекта; это минимальный технический этап, не запуск производства. Не менять main, утверждения, Google, HeyGen, MCP-профиль или личные аккаунты. Не устанавливать FFmpeg/Python/VS Code/модели: сейчас они не нужны.

## 1. Обновление существующей ветки

Проверь origin, текущую ветку feature/codex-pipeline, отсутствие отслеживаемых изменений и собственных локальных коммитов. Выполни git fetch origin и git merge --ff-only origin/feature/codex-pipeline. Разрешён только fast-forward, без merge-коммита. Если ветка другая, история разошлась или неотслеживаемый файл мешает обновлению — остановиться, вернуть точный блокер. Ничего не удалять, не делать reset/clean/stash или форсирование. Старую .playwright-mcp папку сохранить. Работать через имеющийся Git Bash или абсолютный путь Git, постоянный PATH ОС не менять.

Прочитать CODEX_HANDOFF.md целиком, CONTENT_REQUIREMENTS.md, SEO_GROUNDED_PROBE_V2.md и этот документ из актуальной рабочей копии. Зафиксировать фактический HEAD и отставание после обновления.

## 2. Node: сначала проверка, затем условная установка

Ранее MCP уже запускался через отдельный node.exe. Найди его точный executable path в записи запуска MCP или у процесса node.exe; не выводи целиком конфиги, аргументы процессов или environment с секретами. Дополнительно проверь обычный каталог Node и известный LOCALAPPDATA/playwright-mcp. Не искать во всех личных файлах. Проверь обнаруженный runtime прямым вызовом node.exe --version и наличие npm.cmd рядом. Для собственного стенда npm не нужен. Node >=22.13 достаточен; не переустанавливай рабочую версию только из-за PATH.

Если подходящего runtime нет, разрешено скачать официальный Node.js LTS v24.x Windows x64 ZIP с nodejs.org в отдельную папку LOCALAPPDATA/RomanReels/tools. Точную доступную версию выбрать по официальному каталогу, проверить ZIP по соответствующему SHASUMS256.txt, сохранить версию/URL/хеш. При несовпадении или недоступности проверки остановиться. Распаковать только после проверки. Без администратора, перезаписи существующих runtime, изменений системного PATH и конфигурации MCP. Не выполнять скачанные произвольные install-скрипты. Пользоваться абсолютным node.exe или временным PATH только текущего процесса.

## 3. Собственный стенд через настоящий MCP

Создай новый каталог результата вне Git, например LOCALAPPDATA/RomanReels/seo-check/<timestamp>. Из корня актуального репозитория запусти найденным node.exe serve-seo-fixture.mjs broken. Скрипт: roman-reels/scripts/serve-seo-fixture.mjs. Он сообщает случайный адрес 127.0.0.1 и не слушает внешние интерфейсы. Сохрани PID только собственного стенда и его вывод. Не запускать PowerShell-команды с чужими строками из страниц.

Через реальные browser_navigate/browser_evaluate/browser_take_screenshot текущей сессии MCP открывай только этот стенд. Проверь четыре страницы /, /services, /pricing, /contact: title, description, meta robots, canonical, число H1, HTTP-ответ. Проверь собственные /robots.txt и /sitemap.xml, направление /old-services и статус /missing-test-page. Запиши сырые наблюдения с URL и реально выполненные инструменты, без подмены прошлым отчётом. Для редиректа получить исходный статус/Location до перехода, если инструменты позволяют; иначе отметить «не измерено». Не выводить отсутствующий пункт как проверенный.

Главная broken содержит noindex при учебном намерении индексировать её: это проблема директивы, не доказательство реальной Google-индексации. После сбора завершить только свой процесс стенда (не все node.exe/MCP).

Аналогично запустить fixed и сравнить те же проверки. Это два заранее подготовленных состояния, а не автономное исправление Claude. Наличие index,follow снимает конкретный запрет; не обещать попадание в Google и не рекомендовать открыть все страницы любого сайта.

## 4. Сдача

Верни ветку/HEAD, перечень фактических локальных изменений и установок, точный путь/версию Node, текущие MCP-инструменты, наблюдения broken/fixed, имена артефактов, ограничения и завершённые PID стендов. Сохрани отчёт/снимки в каталоге результата, без cookies/секретов. Не коммитить или публиковать пока нет проверки; не отправлять Роману автоматически.

Критерий этапа — действительный сбор собственных наблюдений через MCP на Windows. Это не проверка полного SEO, реального сайта, Search Console, скорости, бесплатной ИИ-связки или HeyGen. Claude Pro/Max — наш инструмент разработки; стоимость пути для зрителя подтверждается отдельно.
