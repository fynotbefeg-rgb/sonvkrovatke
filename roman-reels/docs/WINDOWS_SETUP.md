# Windows — будущая настройка, не действие сейчас

Ноутбук временно недоступен. Этот checklist выполняется позже; cloud/ручной intake независимы.
Избегать публикации RDP/браузера/worker-портов в интернете. Не предполагать наличие мощного GPU.

Формат будущего worker upload: три отдельных hook MP4, общий body и два ending MP4
с квитанцией точного текста/ревизии/SHA-256; INCOMING_SIX_PARTS.md. Drive incoming:
`1Qs3YJQB9Hr8H7B0Fa7MWlwsQ0LLGBPoQ`. Не считать собственные WAV/M4A Романа готовыми
видео аватара и не считать доступ облачного ChatGPT доказательством прав worker.

1. Проверить Windows version/updates, CPU, RAM, свободный SSD, GPU/VRAM, питание и доступный интернет. Сохранить обезличенный результат для выбора вычислительного режима.
2. Установить Git из официального источника; проверить `git --version`, настроить автора без хранения токенов в URL.
3. Установить поддерживаемый Node.js ≥22.13 для текущей SQLite реализации, проверить node/npm; сверить с CI. Зафиксировать точную версию.
4. Установить VS Code; открывать существующую папку, не создавать новый проект.
5. Авторизовать GitHub через допустимый browser/device flow, клонировать существующий repo, fetch automation; включить MFA и безопасный credential manager.
6. Установить Claude Code по актуальной официальной инструкции, выбрать поддерживаемый native Windows или WSL вариант после проверки требований. Пользователь входит в Pro/Max самостоятельно; не копировать OAuth токен в чат.
7. Подключить Codex доступным официальным Windows/WSL способом. Сеанс отдельный от облачного Codex; проверить доступ, не предполагать общие файлы автоматически.
8. `cd roman-reels/pv`, установить зависимости через `npm ci`, проверить bundle/tsc. Не менять lockfile ради обхода ошибок.
9. Установить FFmpeg/ffprobe из проверенного источника, добавить PATH, проверить версии и decode существующего MP4.
10. Установить поддерживаемый Python в отдельном venv. Транскрипцию/torch ставить только после оценки RAM/CPU; не выбирать GPU зависимости вслепую.
11. Создать рабочие ветки от актуальной automation; настроить runtime вне Git, manifests и локальные пути без секретов в репозитории. Результаты синхронизировать через PR.
12. Подготовить отдельный локальный профиль браузера HeyGen с ограничениями ОС. Пользователь выполняет login/2FA; браузерные cookies не экспортировать в GitHub.
13. Проверить текущие Terms и разрешение конкретной UI автоматизации (см. HeyGen документ). Пока gate не снят, использовать только mock worker, не реальные UI команды.
14. После разрешения установить согласованный worker/Playwright, outgoing HTTPS, least-privilege worker credential. Один claim/lease одновременно, тестовый режим по умолчанию.
15. Выбрать защищённый удалённый доступ с iPhone: MFA у выбранного решения, при VPN — закрытая tailnet/ACL, без публичного RDP. Инструмент и стоимость согласовать перед установкой платного варианта.
16. Проверить доступ worker только к incoming Drive и одному тестовому MP4; API credentials в защищённом локальном хранилище. Проверить duplicate-safe upload без логирования токенов.
17. Mock reboot/offline/reconnect и неоднозначный submit: job сохраняется, повторной генерации нет. Реальный bounded test — только после разрешения и согласованного лимита.
18. При необходимости Task Scheduler после входа пользователя: worker запускается без обхода login/2FA; service без интерактивного desktop не считать работающей browser-сессией. Проверить sleep/power и безопасное восстановление.
19. `npm run dev` для локального Remotion preview; проверить звук, субтитры, лицо и safe zones. Не открывать studio наружу без защищённого доступа.
20. Проверить fetch/pull, isolated branches, PR и CI, отсутствие runtime/profile/secrets в diff. Сравнить локальный и cloud render по checksum входов/версиям инструментов.

## Распределение нагрузки после измерений

HeyGen UI требует доступной Windows-сессии; ноутбук выключен → очередь ждёт.
Gemini, утверждения, облачная очередь, обработка уже загруженных MP4, QC/Drive остаются cloud.
Transcription и render выбирать по измеренному RAM/runtime и бюджету; слабый ноутбук может
выполнять только браузер и upload. Не делать его обязательным сервером фабрики.

Результат настройки: hardware report, версии, один source upload, reboot test, один preview,
подтверждение Terms/разрешения и список оставшихся блокеров. До этого автоматизация HeyGen не готова.
