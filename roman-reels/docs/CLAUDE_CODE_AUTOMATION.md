Обновление ТЗ 3.0: prepare-claude-job.mjs теперь собирает [CLAUDE_P1_EXECUTION.md](CLAUDE_P1_EXECUTION.md)
с exact interfaces для Director/контракта v1. Целевая feature-ветка Claude — feature/claude-montage;

## Реализованная часть

В зарегистрированном `roman-reels-check.yml` добавлен выключенный по умолчанию режим `run_claude_task`. Он вызывает reusable `roman-claude-task.yml` из той же automation-ветки; main не нужна и не менялась. Prompt автоматически собирается из `CLAUDE_P1_EXECUTION.md`, фиксируется SHA-256. Пользователь больше не должен копировать каждое задание в чат Claude, когда runtime будет авторизован.

Результат — artifact с patch для проверки Codex. Claude не получает Bash, сторонние MCP или GitHub write token, не коммитит, не меняет main/таблицу и не запускает видео. CLI закреплён на 2.1.296, запуск ограничен 20 turns и 20 минутами workflow. Это ограничение объёма работы, **не гарантированный денежный потолок**. Операции используют лимиты подписки; условия дополнительных расходов проверяются в пользовательском аккаунте. Платный API как запасной способ не используется.

Код runner использует documented headless `--print` и restricted/safe режимы с Read/Edit/Write/Glob/Grep. Результат требует subtype success; только изменения `roman-reels/pv/src/` и `roman-reels/docs/` могут попасть в patch, удаления/переименования отклоняются. Проверки кода выполняет Codex после получения artifact, отдельно от шага с OAuth. Это не техническая гарантия качества предложения: patch нужно просмотреть до применения и протестировать.

## Единовременная настройка

1. Создать отдельный OAuth-токен командой **`claude setup-token`** в собственном терминале с браузерной авторизацией Claude Pro/Max. Обычная сессия Claude в Safari не становится автоматически credential GitHub Actions. Если терминала нет, выбрать и проверить подходящий браузерный терминал; нельзя обещать, что мобильный OAuth flow уже работает. Создание облачного терминала с возможной оплатой требует отдельного согласования.
2. Сохранить результат напрямую в GitHub Actions secret **`CLAUDE_CODE_OAUTH_TOKEN`**. Не отправлять токен/коды входа в ChatGPT, Issues, файлы репозитория или скриншоты.
3. После согласования использования лимита подписки создать repository variable **`ROMAN_CLAUDE_ENABLED=true`**. Без неё runner завершится до установки CLI и до AI-вызова. Это отдельная активация, сейчас её не выполняли.
4. Согласовать первый ограниченный запуск. Codex может выполнить dispatch существующего workflow с `run_claude_task=true`, остальные сервисные флаги false. Затем скачать patch, проверить scope/базовый commit, выполнить проверки и применить подходящие изменения только в automation-ветке.

Нет cron и автоматического запуска при push. Это исключает повторные траты по каждому коммиту и циклы Claude → commit → Claude. После успешного первого теста можно согласовать отдельный механизм очереди задач/триггеров. Прямого вызова пользовательской браузерной сессии Claude и фонового возобновления сессии Codex нет; runner — отдельный процесс Claude Code.

## Проверено и не проверено

Два offline-теста подготовки задания прошли, YAML и diff проверены. Пакет подготовки не вызывает Claude. Авторизация OAuth, установка/запуск CLI в Actions, результат модели и прием patch ещё не проверены. Реальный Claude/платные сервисы для подготовки не запускались.
