# Монтаж Reels: практическое применение ИИ в бизнесе

Дата: 2026-10-10. Разработка Codex поверх движка Claude из PR #6.

## Что действительно проверено

Наш Director и RomanFactoryV1 проверены тестами и предыдущим локальным рендером.
Они уже поддерживают пословные субтитры, смысловые плашки, списки и приближения.
Внешние ролики Dan Martell пока проверены только как кандидаты по публичным
метрикам: их видео не было просмотрено. YouTube возвращает ограничение загрузки,
а из рабочей среды — HTTP 403. Это не покадровый разбор и не воспроизведение
его монтажа. Источники и ограничения статистики: EXTERNAL_REFERENCES_RESEARCH.md.

## Вывод для нашего формата

Практическому ролику о бизнесе нужен наглядный пример операции: исходное
сообщение клиента → черновик ответа → проверка сотрудником. Одних названий
инструментов недостаточно для объяснения пользы. Это наше редакционное решение,
а не вывод о невиденном внешнем видео и не обещание высоких охватов.

Для близкого к выбранному референсу результата ещё нужны:

1. Доступный для просмотра видеофайл референса: темп, длительность вставок,
   крупность лица, типографика и композиция должны оцениваться по кадрам.
2. Утверждённые Романом три хука и общий основной текст с актуальными хешами.
3. Четыре исходника в incoming: три отдельных хука и одна основа. Сборщик
   SHARED_BODY_ASSEMBLY.md уже создаёт три полных исходника для монтажа.
4. Демонстрационные материалы с правами: свои записи интерфейсов или свои
   иллюстрации, без личных данных и без обещания несуществующих результатов.
5. Тайминги реальной речи, согласованный фирменный стиль и визуальная проверка
   первого примера на телефоне. Автоматический QC художественное качество не оценивает.

## Что реализовано сейчас

Director v1.1 использует существующий тип события `interface` и контракт 1.0.0.
Явно переданное изображение `tool-claude` заменяет плашку на слове Claude.
Если материала нет, прежняя плашка сохраняется. Без материалов планы всех трёх
существующих вариантов остаются идентичными. Событие привязано к индексу слова;
его длительность ограничена следующими акцентами и концом видео.

RomanFactoryV1 показывает локальное изображение в верхней безопасной полосе.
Добавлена собственная иллюстрация `pv/public/rr/demos/client-reply.svg`:
«Сообщение клиента / Черновик ответа». Она явно помечена как условное демо,
не изображает настоящий интерфейс Claude и не использует клиентские данные.
Речь, субтитры, тайминги, утверждения и общий основной текст не изменяются.

Обёртка рендера теперь сохраняет visualAssets, проверяет наличие локальных
изображений и обязательную ссылку/описание прав. Наличие rightsReference —
требование к метаданным, а не автоматическое юридическое подтверждение прав.
Звук сохраняется прежним механизмом копирования оригинальной AAC-дорожки
и проверки PCM-хеша/аудиочасов. Публикация и production-статус отключены.

## Повторение теста

Готовое тестовое задание: `research/business-montage-v1/development-job.json`.
Оно подготовлено из существующего development-задания
`research/first-montage-v1/assembled-jobs/R-ai-shared-body-fixture-h1-job.json`.
с добавлением в visualAssets:

```json
{
  "id": "tool-claude",
  "type": "image",
  "localPath": "rr/demos/client-reply.svg",
  "rightsReference": "Original illustrative demo; not Claude UI, no customer data"
}
```

После установки зафиксированных зависимостей запустить из корня репозитория:

```sh
python roman-reels/scripts/run-development-montage.py /path/to/demo-job.json \
  --out /path/to/new-output --browser-executable /usr/bin/chromium
```

Последний аргумент нужен только при использовании уже установленного Chromium.
Папка вывода должна быть новой. Исходный MP4 не хранится в Git и должен
существовать по указанному в задании локальному пути с совпадающим SHA-256.
Это старый технический пример речи, а не ролик по новому пилотному сценарию
из таблицы и не подтверждение утверждения Романа.

## Ограничения и следующий этап

Полный h1 рендер прошёл технический QC: 1080×1920, 25 кадров/с, 40,24 с,
H.264/AAC, полное декодирование. Проверка исходной AAC-дорожки подтвердила
совпадение PCM-хеша и аудиочасов. Просмотрены извлечённые контрольные кадры
на 2, 19, 35 и 37 секундах, а не полное воспроизведение. Прошли tsc, 27 TS
и 27 Python проверок. h2/h3 повторно не рендерились.

[Технический пример на Google Drive](https://drive.google.com/file/d/1EeiOWmnJFF1DBCkNYnp29a_rURyldfhf/view?usp=drivesdk).
Загрузка и метаданные подтверждены. Доступ есть у владельца и сервисного
аккаунта рендера; доступ Романа к новому файлу пока не предоставлен.
Отчёты QC, хеши, план и контрольные кадры: `research/business-montage-v1/`.

Сейчас поддержаны только локальные изображения; не реализованы динамическая
запись интерфейсов, распознавание лица, подбор B-roll и свободный смысловой
анализ. Безопасная полоса рассчитана на существующий исходник, а не на любую
крупность лица. Очень близко стоящие названия инструментов могут дать короткие
вставки: для длинного объяснения нужен отдельный монтажный сценарий и проверка
читаемости. Распознанная речь требует отдельной проверки человеком.

Следующий этап после просмотра референса: подготовить покадровую карту формата
и отдельный набор демонстраций под утверждённую тему. Текст и утверждения
необходимо сохранить; изменение сценария требует повторного утверждения.
