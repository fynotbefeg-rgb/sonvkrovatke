# Связь очереди бота с передачей заданий ноутбуку — кандидат

2026-10-13. Код и автономные тесты, без живого запуска. Генерация, загрузка видео, монтаж и рендер не затрагиваются.

## Что делает `prepareQueueDelivery`

Вход: путь к SQLite очереди бота, явный пакет согласования одной темы/ревизии (`shared-review` v1 — тот же,
что у `plan-approved-four-part-jobs.mjs`), каталог будущих скачиваний, функция свежего аутентифицированного
чтения очереди Google, текущие байты почтового ящика и слота подтверждения, каталог outbox.

1. Открывает базу бота **только для чтения** и берёт ожидающие задания (`waiting_for_*`) этой темы/ревизии.
   Нужны ровно три (хуки 1–3); иначе `awaiting_queue_jobs`. Состояние заданий не меняется.
2. Заново читает согласования. Каждый поставленный в очередь вариант должен по-прежнему быть утверждён с тем же
   `production_key` (версия, ревизия, хеш текста). Иначе `approval_changed_or_revoked`. Строки очереди — не
   полномочие.
3. Строит план существующим `planApprovedUploads` с ожидаемыми путями
   `<downloads>\<topic>\v<rev>\<role>.mp4` (загрузчик сам ждёт готовности файлов) и конверт `buildDelivery`.
4. Проверка координатора `mayReplaceDelivery`: другой неподтверждённый пакет в ящике → `blocked /
   previous_not_acknowledged`, конверт не создаётся. Пустой ящик и продление того же плана разрешены.
5. Пишет конверт эксклюзивно в outbox (`<deliveryId>.<issuedAt>.json`). Пока конверт не истёк, повтор
   возвращает `already_prepared` с тем же файлом — дубликатов нет.

Все результаты содержат `generationAllowed/uploadStarted/renderAllowed=false` и
`currentApprovalRecheckRequired=true`. Упакованные тексты получают статус `pending_approval` без имён утверждающих.

## Открытое решение — нужен владелец/Codex

Бот (координатор) теперь работает на самом ноутбуке. Прежний контракт: почтовый ящик пишет только
сериализованный облачный издатель (`publish-windows-plan.py`, сервисный аккаунт), а workflow публикации не
настроен. Варианты доставки конверта из outbox:
- (а) облачный издатель забирает конверт (нужен канал outbox → облако);
- (б) локальная передача в приёмник ноутбука без Drive;
- (в) публикация в ящик OAuth владельца — меняет принятую модель «один облачный писатель».
Мост не выбирает транспорт и ничего не публикует.

Также нужен источник пакета `shared-review` для темы: Роман ещё не выбрал и не утвердил темы, старые отметки не
считаются согласованием. До этого живых данных для моста нет.

## Тесты

`queue-delivery-bridge.test.mjs`, 6 офлайн-тестов на временной SQLite с настоящим `ProductionQueue`: полный
путь до конверта без изменения очереди, повтор без дубликата, неполная очередь, отозванное и изменённое
согласование, несовпадающий пакет, блокировка неподтверждённого предыдущего пакета и продление, чтение только
для чтения и пути Windows. Зарегистрирован в Linux и Windows CI.
