# Технический и SEO-аудит сайта — исследование для версии 5

Дата: 2026-10-11. Новое направление расширяет v4, а не наследует её утверждение.
Цель ролика: показать владельцу бизнеса проверяемые проблемы и порядок
исправления. Формулировка «полноценный аудит» описывает направление разработки;
нынешняя учебная демонстрация не является полным аудитом произвольного сайта.

## Что проверено

`scripts/run-technical-seo-demo.mjs` автоматически собирает данные четырёх
заданных страниц собственного loopback-сайта. Проверки заранее написаны Codex;
девять дефектов намеренно заложены автором. До: 1 PASS / 9 FAIL.
После исправлений: 10 PASS / 0 FAIL. Один положительный контроль — доступность
четырёх страниц — проходит в обоих состояниях. Никакие проверки не пропускались.

| Проверка | Наблюдение до | После | Приоритет в учебном отчёте |
| --- | --- | --- | --- |
| Четыре страницы HTTP 200 | PASS | PASS | P1 |
| robots.txt: обход /services | Disallow: /services | Разрешён | P1 |
| Запрет индексации | Главная: noindex | Запрет снят | P1 |
| Sitemap | Нет /services, /gone даёт 404 | Все 4 URL доступны | P2 |
| Title | Главная и услуги одинаковые | Разные | P2 |
| Description | У услуг отсутствует | Заполнено | P3 |
| Canonical | Услуги указывают на главную | Услуги указывают на себя | P1 |
| Заголовки | Два H1 по учебному требованию | Один | P3 |
| Постоянный переезд услуг | 302 на главную | 301 на услуги | P2 |
| Отсутствующая страница | 200 с текстом «не найдено» | 404 | P2 |

Приоритеты задаёт учебный чек-лист, не модель. Каждая находка имеет ожидаемое
состояние и наблюдение. Это не предсказание потерь денег или SEO-позиций.
Наличие description, self-canonical и одного H1 — требования конкретной модели
сайта: отсутствие этих признаков не является универсальным доказательством
ошибки/санкций поисковой системы. Повторяющееся содержимое страниц и выбор Google
не оценены; canonical проверен относительно согласованной структуры.

Отдельный предыдущий функциональный опыт: девять браузерных сценариев,
восемь намеренных дефектов, затем 9 PASS. Проверены мобильное меню, переполнение,
форма и запись в локальном приёмнике. Эти два опыта нельзя выдавать за единый
аудит одного клиентского сайта или реальную интеграцию с CRM.

## Что нужно для широкого клиентского аудита

| Блок | Инструмент / данные | Текущее состояние |
| --- | --- | --- |
| Пути клиента | Playwright, согласованные сценарии, тестовый приёмник | Учебный опыт выполнен |
| Обход и техническое SEO | Ограниченный HTTP/DOM crawler, стандартный robots/XML parser, заголовки ответа | Только 4-URL fixture, не универсальный crawler |
| Фактическая индексация и выбранный canonical | Search Console: Page Indexing и URL Inspection | Нет доступа/выгрузки сайта; не проверено |
| Скорость | Lighthouse/PageSpeed лабораторно; CrUX/Search Console для полевых LCP/INP/CLS | Не измерено; loopback не заменяет реальных посетителей |
| Содержание и стратегия | Семантика, намерения запросов, дубли, внутренние ссылки, конкуренты, данные владельца | Не проведено |
| Разметка/локализации/варианты | Rich Results Test, hreflang, JS rendering, пагинация, URL-параметры | Не проведено |

HTTPS, доступность, защита и персональные данные требуют отдельных проверок.
Аудит SEO не равен тесту на проникновение. Исправления реального сайта не
выполняются автоматически без отдельной задачи и проверки. Формы тестировать
на копии с безопасным приёмником; настоящие заявки не отправлять без разрешения.
Для клиентского crawler нужны лимиты, стандартные парсеры, SSRF-защита,
запрет перехода на неизвестные/private origins и отчёт покрытия.

## Актуальные первичные источники

Открыты 2026-10-11:

- https://developers.google.com/search/docs/crawling-indexing/block-indexing — noindex
  работает после обхода и обработки; robots-блокировка может помешать прочитать его.
- https://developers.google.com/search/docs/crawling-indexing/robots/intro — robots
  ограничивает обход; запрет обхода не гарантирует удаления URL из индекса.
- https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls —
  canonical является сигналом предпочтения, а не доказательством выбора Google.
- https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview —
  sitemap помогает обнаруживать страницы, не гарантирует индексации.
- https://developers.google.com/search/docs/appearance/title-link — title помогает
  описанию результата; Google может формировать заголовок иначе.
- https://developers.google.com/search/docs/appearance/snippet — description может
  использоваться для сниппета; это не гарантия его отображения.
- https://developers.google.com/search/docs/appearance/core-web-vitals — нужны
  измерения LCP/INP/CLS; это не полная оценка SEO.
- https://developer.chrome.com/docs/lighthouse/performance/performance-scoring —
  лабораторный балл зависит от условий и метрик, не равен полевому результату.

Популярный внешний ролик с подтверждёнными охватами по новому углу пока не найден.
Не выдавать собственную демонстрацию за анализ такого референса.

## Воспроизведение

```bash
node roman-reels/scripts/run-technical-seo-demo.mjs \
  /path/to/dependency-root /path/to/chromium /tmp/fresh-seo-evidence
```

Уже установлен playwright-core, новые пакеты не ставились. По умолчанию
browser sandbox включён. В текущем контейнере для своего изолированного
loopback-fixture нужен явный `SITE_AUDIT_DEMO_NO_SANDBOX=true`. Не переносить
исключение на внешние сайты или авторизованные профили.
`research/site-technical-seo/evidence/audit-report.json` содержит время, хеши,
наблюдения и ограничения; рядом 8 контрольных скриншотов.

## Речь и честная роль ИИ

Сначала сбор технических данных, затем объяснение и задачи по доказательствам,
после исправлений — повторные измерения. Gemini получает проверенный бриф для
основы и трёх хуков; это генерация речи, а не выполненный моделью аудит сайта.
Подключённый браузер Claude, автономный поиск и аудит одним промптом не проверены.
Нельзя говорить «полностью проверили сайт» или обещать рост позиций.
Бриф v5 готов; точный текст и каждый хук ждут нового утверждения Романа.
