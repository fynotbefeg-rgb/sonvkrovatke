# Отдельные окончания для Instagram и TikTok

Дата: 2026-10-10. Первоначальный этап ниже — редакционные черновики и проверенная
низкоуровневая склейка трёх частей. Реальные аккаунты ManyChat/HeyGen не подключались.
Обновление: отдельная media schema v2, intake и speech adapter шести development
вариантов реализованы и проверены, см. INCOMING_SIX_PARTS.md. Production ещё не подключён.

Это предложения для утверждения, не обещание уже настроенного ответа бота.
Точный текст каждого окончания входит в утверждение полной речи. Утверждение
только темы или хука недостаточно. Пока текст не утверждён, голос не записывать.

## Что проверено по ManyChat

Официальные страницы открыты 2026-10-10:

- [TikTok: User sends a message](https://help.manychat.com/hc/en-us/articles/17508399106844-Set-up-your-first-TikTok-automation-in-Manychat-User-sends-a-message):
  выбранный путь — входящее личное сообщение TikTok Business account и keyword.
  Документация также перечисляет Ref URL/QR; утверждение, что у TikTok вообще
  существует только один вид триггера, было бы неточным. Для нашего CTA не
  используем комментарии. Описаны ограничения окна сообщений и ссылки,
  которые нельзя считать кликабельными в TikTok DM.
- [Instagram: Post and Reel Comments](https://help.manychat.com/hc/en-us/articles/14281316989724-Instagram-Post-and-Reel-Comments-trigger):
  keyword в комментарии может запускать приватный ответ. Есть ограничения
  первого комментария и дальнейшей переписки/согласия пользователя.

Документация сервиса не подтверждает доступность функций в аккаунте Романа.
Перед реальным использованием проверить тип/регион аккаунта, подключение,
разрешения, правильный Reel/keyword и одну тестовую переписку. Публикация и
автоматические сообщения не запускались, дополнительных платных сервисов нет.

## Реализовано

`platform-ending-drafts.mjs` — отдельный opt-in модуль редакционных черновиков.
Он сохраняет три хука и общую основу и создаёт шесть полных текстов на тему:
по три для Instagram и TikTok. Platform ID отделяет их от старых вариантов.
Статусы pending_approval; никаких данных об утверждении Романа не создаётся.
Hash полного текста включает окончание. TikTok comment CTA отвергается.
Старые shared-body callers не изменены.

Для обеих выбранных тем подготовлены 12 pending текстов в
`research/platform-ending-drafts-v2.json`. Это шесть исходных записей на тему:
hook1, hook2, hook3, body, ending-instagram, ending-tiktok. Две площадки дают
шесть экспортов из трёх уникальных hook/body версий. Это не обещание
удвоенного объёма уникальных сценариев или готовых production-видео.

`assemble-source-set.py::concatenate` принимает необязательное окончание,
нормализует все части и склеивает в правильном порядке. Реальный FFmpeg-тест
на синтетических цветных фрагментах проверил последовательность, длительность,
1080×1920, звук и QC. Это технический тест, не новый ролик Романа.

## Что ещё требуется для живого конвейера

Media source-set v1 и assembled-jobs пока описывают две части; их не расширяем
молча. Editorial draftVersion 2.0.0 не является media assemblyVersion 2.0.0.
Для полного production-пути нужны отдельная согласованная media-схема/адаптер,
checksum и approval binding окончания, тайминги его реальной речи и перенос
после body. Нельзя использовать старый wordTimings JSON для добавленного звука.
Director должен получить уже собранный полный source с окончанием и свежими
словами; повторно склеивать части внутри Remotion не требуется.

Простая таблица осталась A:G; хуки и B/D решения не менялись. Интерфейс
утверждения основы/окончаний в Telegram пока не подключён. Windows и разрешение
HeyGen остаются прежними зависимостями.

Проверки: 6 platform-ending tests, 3 shared-body regression tests и 5 реальных
source-set tests прошли. Старые source-set v1 результаты продолжают проходить.
